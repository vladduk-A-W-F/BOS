# BoS · фактичні перевірки та межі

Поточний стан задач і приймання: [PROGRESS_UA.md](PROGRESS_UA.md). Повний набір незмінний: 11 критеріїв, тільки їхнє реальне виконання дозволяє оголосити реліз. Локально зелені компоненти не заміняють PostgreSQL, браузер, Windows або незалежне клієнтське приймання.

## Як відтворити поточний набір

З підготовленого Python 3.12 середовища, з кореня BoS:

```bash
BOS_PYTHON=.venv/bin/python ./scripts/verify.sh --suite full --output evidence/manual-full/report.json
```

Windows / PowerShell:

```powershell
.\scripts\verify.ps1 -Suite full -Python .\.venv\Scripts\python.exe -Output evidence/manual-full/report.json
```

`verify` готує ізольований код, нові синтетичні бази, контрольне джерело й окремі файли. Не підкладайте робочу базу для запуску старих окремих скриптів. Звіт і ненульовий код зберігають відсутні середовища та нереалізовані перевірки червоними. Потрібні налаштування PostgreSQL/CI, wheels/Caddy та Windows runner наведені в [CI_UA.md](CI_UA.md), [SERVER_INSTALL_UA.md](SERVER_INSTALL_UA.md), [WINDOWS_RUNNER_UA.md](WINDOWS_RUNNER_UA.md).

## Межі висновку

Фактичне базове середовище локальних перевірок: Linux, Python 3.12.14, Django 6.0.5, SQLite 3.53.1. Concurrency перевіряється реальними одночасними запитами, але SQLite conflict не доводить PostgreSQL row-lock waiting. Babel/Node і extracted-JS checks не є браузерним прийманням. Жоден PDF або опис кроків не доводить завершення операції в браузері.

A09 має відому нестабільність завеликого запиту, A10 — неприйняте оновлення/rollback, A11 — відсутнє приймання браузера й Windows. F04 — відкритий операторський bootstrap першого адміністратора. Зовнішня модель, банки, OCR, реальний пілот, навантаження та Python 3.15 не прийняті. Число користувачів і клієнтська економія цими синтетичними перевірками не встановлювалися.
