# BoS · виписки та звірка оплат

BoS допомагає знайти джерело кожного руху грошей і побачити, які рахунки клієнтів він погашає. Виписка, запис журналу та оплата рахунку зберігаються окремо: повторний імпорт або повторне погодження не повинні проводити суму вдруге.

Локальні результати C03 збережено у [звіті модуля](../evidence/C03/RESULT_UA.md). Загальне приймання визначає [стан проєкту](PROGRESS_UA.md). Банк автоматично не підключений; використовується файл CSV установленого формату.

## Де працювати

CEO відкриває **Фінанси → Операції → Виписки**. У вкладці **Журнал** показані надходження, витрати й чистий рух за вибраними валютою та періодом. EUR, USD та UAH не складаються між собою. Архівні транзакції залишаються в підсумках, бо архівування не скасовує рух грошей.

Менеджер зберігає попередній доступ до дозволених записів через свій режим перегляду. Імпорт і фінансова звірка доступні CEO.

Навчальний файл: [BoS_Statement_Demo.csv](examples/BoS_Statement_Demo.csv). Він містить три незалежні суми EUR/USD/UAH без автоматичних прив’язок до рахунків. Порядок показу й звірки — у [пам’ятці за ролями](ROLE_GUIDE_UA.md).

## Завантажити та перевірити джерело

1. Оберіть CSV, введіть код документа, версію та назву. До одного файла допускається 1 000 рядків, розмір — до 1 MiB.
2. Перевірте результат розбору, кількість рядків, суми окремо за валютами та оригінал документа. Помилка формату відхиляє файл цілком; система вказує запис і стовпець.
3. Підтвердьте перевірку джерела. Неперевірений документ не є підставою для імпорту.
4. Оберіть наявну пару «система-джерело / локальний рахунок» або явно введіть нову. Вона визначає, до якого потоку належать рядки, і не є підключенням до банку.
5. Відкрийте попередній перегляд імпорту: скільки рядків буде створено, скільки вже є та які суми містить джерело. Погодьте дію й відкрийте отриманий імпорт.

**Імпорт сам по собі не створює транзакцій журналу й не погашає рахунків.** Кожен рядок можна відкрити окремо: первісний документ, точні поля CSV, запис журналу, рознесення та поточний стан рахунків.

## Звірити рядок

У картці рядка є три послідовні рішення.

| Рішення | Що обрати | Що зміниться |
|---|---|---|
| Відображення грошей | Створити запис або прив’язати наявну транзакцію | Повна сума рядка враховується в журналі один раз. |
| Контрагент | Явне ручне зіставлення, відповідність початкового імпорту або наявне зарплатне джерело | Зберігається перевірена підстава зв’язку. |
| Рознесення надходження | Нова оплата рахунку або прив’язка вже врахованої оплати | Нова оплата збільшує сплачене за рахунком; прив’язка старої не збільшує його повторно. |

Для нового запису введіть категорію й опис. Суму, валюту, напрям та дату BoS бере з рядка виписки. Для наявного запису система перевіряє точну відповідність; список кандидатів можна продовжити кнопкою **Ще джерела**.

Виберіть контрагента та поясніть підставу звірки. Якщо контрагент не визначений, можна явно зберегти запис без нього, але без погашення клієнтських рахунків. Наявне зарплатне джерело зв’язується тільки з уже створеною витратною транзакцією; зарплата тут заново не нараховується.

Для кожного рознесення виберіть рахунок, суму, спосіб зіставлення та підставу. Якщо оплата вже існує, виберіть саме її історичну подію. Вихідний рух не розноситься на рахунки клієнтів.

Перед погодженням BoS показує, які записи з’являться та як зміниться сума до оплати. Після погодження відкривається квитанція цієї дії; поточну картку й джерела можна відкрити поруч.

## Приклад часткової оплати

За випискою надійшло **123,45 USD**. У журналі вже є відповідна транзакція, а рахунок клієнта на **2,34 USD** ще не оплачено.

- Обираємо наявну транзакцію: новий рух грошей — **0,00 USD**.
- Створюємо рознесення **2,34 USD** на рахунок: сума до оплати стає **0,00 USD**.
- Нерознесений залишок надходження — **121,11 USD**. Це гроші без прив’язки до інших клієнтських рахунків, а не додаткова транзакція.

## Як читати показники

| Показник | Значення |
|---|---|
| За випискою | Рядки перевірених імпортів, без повторного підрахунку спільних рядків. |
| У журналі | Рядки виписки, уже зв’язані з транзакцією. |
| Ще не в журналі | Імпортовані рядки, які очікують звірки. |
| Рознесено | Частина вхідних сум, пов’язана з клієнтськими рахунками. |
| Нерознесено | Частина вхідних сум без такого зв’язку. |
| Чистий рух періоду | Надходження мінус витрати; це не залишок банківського рахунку. |

Ці виміри не додаються між собою. Ручні транзакції журналу без виписки не приписуються конкретному локальному рахунку виписки.

## Повтор, помилка та втрачена відповідь

Однакові байти у тій самій парі джерело/рахунок повертають перший результат імпорту. Файл із частково спільними рядками повторно використовує вже відомі записи. Якщо однаковий зовнішній ID містить інші фінансові поля, BoS показує конфлікт і не застосовує файл частково.

Якщо відповідь після погодження втрачена, скористайтеся **Погодження без квитанції → Перевірити те саме погодження**. Номер наміру зберігається до відправлення. Повтор працює з тим самим номером; помилка чи відсутня відповідь не означає, що операцію не виконано. Не створюйте заміну невідомому наміру.

Ці ідентифікатори зберігаються у поточній вкладці. Після її закриття або зміни сесії факт виконання потрібно перевіряти за карткою імпорту чи рядка. Для невідомого результату завантаження знайдіть документ за його кодом і версією, перш ніж повторювати завантаження.

Кнопка завантаження оригіналу повертає точні байти файла. Експорт імпорту містить посилання та поточні стани для перевірки; це окремий файл, який не підміняє оригінал.

## Межі цього модуля

Реалізовано CSV, журнал грошей та погашення клієнтських рахунків. Автоматичних банківських команд, обміну валют, початкового або кінцевого банківського залишку, обліку кредиторки постачальника чи автоматичного повернення грошей тут немає. Претензія постачальнику залишається окремим процесом закупівлі.
