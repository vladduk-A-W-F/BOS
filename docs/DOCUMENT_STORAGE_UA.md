# Документи BoS

Новий документ завантажується через чинний реєстр. Кожна версія отримує окремий оригінал, SHA-256 і точний розмір у байтах. Назва файла лишається в картці; технічний ключ не є публічним посиланням. Перегляд тексту, історія версій і права користувача збережені.

Перед видачею оригіналу, погодженням або використанням документа для допуску партії та зміни версії виробу BoS звіряє фактичні байти. Пошкоджений чи відсутній оригінал спричиняє відмову з поясненням. Контрольна сума та історичні записи автоматично не виправляються. Потрібно звірити документ із перевіреною резервною копією.

Старі документи без файлового ключа читаються зі збереженого BLOB за його SHA. Для запису лише з текстом допустимі точні UTF-8 байти, що відповідають історичній контрольній сумі. Порожній оригінал залишається порожнім. Якщо приватний ключ уже встановлено, старий BLOB не підставляється замість відсутнього або пошкодженого файла.

## Обсяг сховища

| Параметр | Значення |
|---|---|
| Один оригінал | До 10 485 760 байтів включно, 10 MiB |
| Загальна квота за замовчуванням | 1 073 741 824 байти, 1 GiB |
| Налаштування Django | `BOS_DOCUMENT_QUOTA_BYTES`: ціле невід’ємне число байтів |
| Що враховується | Усі фізичні файли MEDIA_ROOT та всі історичні Document BLOB |
| Версії, архіви, файли без зв’язку | Враховуються; архівація не звільняє квоту |
| Нульова квота | Допускає порожній файл, якщо вже зайнято 0 байтів |
| Місце на диску | Квота не гарантує наявності вільного диска |

Квота задається адміністратором у конфігурації Django. Вебредагування цього параметра не додано. Значення `True`, текст, `None` або від’ємне число не приймаються. Для перенесення зі збереженням історичних BLOB потрібне місце і для BLOB, і для нової файлової копії.

Одночасні завантаження використовують спільне блокування запису ERP. Конфлікт паралельної операції повертає 409; перевищення квоти — 422. Після SQL-відмови BoS прибирає лише власний щойно створений файл. Аварійне завершення процесу може залишити незв’язаний файл; він продовжує займати квоту й не видаляється автоматично.

## Приватність і перенесення

Прямий HTTP доступ до MEDIA_ROOT закритий, зокрема в DEBUG. Видача оригіналу потребує видимості документа та окремого дозволу. На Linux нові приватні каталоги мають права 0700, файли — 0600; старі каталоги чату не змінюються. Web server не має видавати MEDIA_ROOT. Фактичне приймання Windows ACL ще не виконано.

A08 виконує перенесення спочатку на новій ізольованій копії БД і файлів. Перевіряються всі записи, потім створюються точні файлові копії. Номери, версії, зв’язки, BLOB, текст, статус і доступ зберігаються. Повтор прийнятого плану не створює нових документів чи ключів. Один непридатний запис робить план неповним; такий план не застосовується.

Для старих вкладень чату без контрольної суми можна зафіксувати SHA фактичного файла на момент звірки. Це не підтверджує його справжність на момент початкового завантаження. Відсутні вкладення не замінюються порожніми файлами. Зовнішню модель і завантаження файлів до неї не ввімкнено.

Перенесення документів A08 не замінює повний backup/restore A10 або приймання релізу. Точні команди та результати локального прогону зберігаються в `evidence/A08/`.

## Репетиція на копії SQLite

З активованого Python-середовища BoS виконайте команду, підставивши абсолютні шляхи до окремої копії бази та відповідного їй сховища:

```bash
python scripts/check_document_migration.py --source-db /absolute/copy/database.sqlite3 --source-media /absolute/copy/media --output-dir /absolute/new-rehearsal
```

Каталог результатів має бути новим, поза checkout і поза джерельним сховищем. Команда спочатку створює власну копію, працює лише з нею та створює ще одну копію для перевірки відновлення. `plan.json` описує джерела й потрібне місце; `report.json` містить результат, SHA, кількість нових файлів та перевірку незмінності входу. Непридатні джерела перелічуються за моделлю та ID; команда відмовляє з ненульовим кодом завершення.

Успішна репетиція не перемикає робочу інсталяцію на нову базу. PostgreSQL і Windows для цього сценарію ще не прийняті.
