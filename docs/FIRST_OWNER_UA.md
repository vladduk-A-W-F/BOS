# Перший керівник окремої установки BoS

`bootstrap_bos_owner` створює бізнес-керівника з роллю `ceo` після міграцій **порожньої робочої бази**. Команда не запускає сервер, не імпортує навчальні дані й не активує production. Спочатку явно виберіть конфігурацію саме нової установки; її `BOS_DATA_MODE` має бути `working`.

Для вже підготовленої серверної установки використовуйте її приватний Python, каталог release і власну конфігурацію середовища `server_settings`:

```text
python manage.py bootstrap_bos_owner --settings=server_settings --username owner
```

Команда двічі запитує пароль приховано. Пароль має містити 12–512 символів, не бути поширеним, суто числовим або надто подібним до логіна. Додаткові налаштовані Django password validators також застосовуються. Для автоматизації є `--password-stdin`: передайте один рядок через stdin із захищеного процесу або менеджера секретів. Не записуйте пароль у командний рядок, shell history, файли репозиторію чи журнали.

Новий керівник може входити через звичайну форму BoS (`/api/auth/login/`) та використовує чинну серверну політику CEO. Обліковий запис активний, має рівно одну бізнес-роль `ceo`, не є `staff` або `superuser`; працівник автоматично не створюється. Це окремо від технічного Django admin: `createsuperuser` без бізнес-ролі не дає входу в бізнес-API BoS.

За замовчуванням команда не додає окремих дозволів документів або експорту. Чинна роль CEO вже дозволяє читати доступні документи; цей контракт не змінюється. За потреби оператор явно додає:

- `--allow-document-download` — `operations.view_document` і `operations.download_document`;
- `--allow-workspace-export` — `operations.export_workspace`.

Наявні користувачі, групи, сесії, бізнес-записи (включно з архівними), налаштування чи попередній bootstrap забороняють команду. Системні `Permission` і `ContentType`, створені міграціями, допустимі. Маркер `initial_business_owner`, користувач, роль, дозволи та аудит створюються в одній транзакції. Два одночасні bootstrap не можуть створити двох керівників. Невдалий виклик відкочується; повтор після успіху відмовляє і не змінює пароль або роль. Команда не видаляє маркери та не ремонтує частково заповнену установку.

Проводьте bootstrap до відкриття сервера та інших процесів запису. Блокування серіалізує саме цю команду; воно не оголошує довільні зовнішні writer-процеси зупиненими. Не запускайте її на наявній установці, навчальній базі або історичній копії. Після успіху перевірте звичайний вхід через TLS-поставку вашої установки. Сам успішний bootstrap не є прийманням TLS, backup/restore, продуктивності чи допуском пілота.
