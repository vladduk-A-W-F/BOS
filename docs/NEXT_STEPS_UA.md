# BoS · наступні кроки

Поточні результати й 30 задач ведуться у [PROGRESS_UA.md](PROGRESS_UA.md). Цей документ пояснює умови наступного етапу; він не заміняє журнал перевірок і не обіцяє дату релізу.

## Перед клієнтським пілотом

| Потрібно | Конкретний результат |
|---|---|
| CI саме BoS | Адреса й доступ до репозиторію цього застосунку. FOS — окремий проєкт. |
| PostgreSQL і браузер | Реальні прогони незмінних критеріїв на ізольованих синтетичних даних; source-review не заміняє браузер. |
| Windows / Python 3.12 | Фактична чиста установка та звіт того самого коду. Python 3.15 не приймався. |
| Серверні умови | Закриття відомої нестабільності A09 та дозволене, перевірене оновлення/rollback A10. Поточні обмеження й ліміти спроб збережено у PROGRESS. |
| Дані D01 | Відповідальний клієнта, 3–5 погоджених замовлень, довідники, одиниці, залишки, документи, права та один формат виписки. |
| Незалежне приймання | Усі 11 критеріїв і приймання людиною. Поки повний verify не повертає 0, готовність не заявляється. |

Окремо перед пілотом погоджуються його обсяг і договір: право обробки даних, порядок їх вивантаження й видалення, належність доробок і канал підтримки. Платежі, сервер, домен та публікація не виконувались.

## Що вже має локальну реалізацію

Облікові записи й рольові права; контрольовані записи; приватні документи; закупівля з перевіреної пропозиції; початковий імпорт; повернення й коригування; доручення з відповідальним, строком і результатом; CSV-виписки та звірка оплат; резервне копіювання та відновлення в нову керовану установку. Межі кожного модуля й фактичні результати — у [ROLE_GUIDE_UA.md](ROLE_GUIDE_UA.md) і PROGRESS.

## Відкладений обсяг

| Задачі | Умова повернення | Попередня оцінка |
|---|---|---|
| B04–B07: виробниче розширення | Рішення про власне виробництво й погоджений процес клієнта | За окремими задачами прийнятого плану |
| B08: структуровані вимоги й різниця версій | Після погодженого пілота | 4–7 людино-днів |
| B09: OCR | Погоджені типи реальних сканів та інженерний еталон | 5–10 людино-днів |
| C02: зовнішній AI-адаптер | Окреме рішення про модель, обсяг і витрати | 6–10 людино-днів |
| C04: сповіщення | Адресат, причина та правила закриття | 2–4 людино-дні |
| D02: поділ UI | Після приймання чинного процесу | 3–5 людино-днів |
| D05/D06: пілот і наступний модуль | Незалежне приймання; щонайменше 10 робочих днів реального використання | 2–4 / 1–2 людино-дні роботи |

Оцінки не є строками AI-виконання або датами релізу. Shared-DB SaaS, новий framework, черги та локальна LLM не входять у поточний обсяг. Перший реальний пілот використовує одну компанію в окремій установці; фінансову економію визначають лише після вимірювання.
