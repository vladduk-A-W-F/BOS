# QA, незалежний review та підготовка пакетів

20.09.2026 власник доручив відокремити перевірки й підготовку релізів; головний затверджує та застосовує.

| Роль | Обов'язок | Вихід |
|---|---|---|
| bos_implementer | Зміни у власному allowlist | Source, diff, авторські результати |
| bos_test_ci | Виконання точних попередньо дозволених QA-команд у призначеному середовищі | Raw output, exit codes, пропуски, ліміти й авторський звіт |
| bos_reviewer | Незалежна перевірка чужого diff і raw evidence | ACCEPT_SCOPED / REJECT / BLOCKED |
| bos_release_packager | Підготовка незмінного пакета й плану застосування | DRAFT / READY_FOR_ORCHESTRATOR_DECISION |
| Головний і єдиний інтегратор | Рішення для точного пакета, послідовне застосування | Рішення й окрема квитанція застосування |
| Контролер | Сверка власників, source, доказів, зайнятості та стадій | Індекс і повідомлення лише про суттєві факти |

Root при призначенні задає існуючу картку, source, залежності, копію, allowlist, точні команди/середовище/залишок ліміту й критерій. QA сам виконує цей обсяг. Нова команда/source, CI або повтор за межами призначення потребують відповідної авторизації; історичні відмови не обходяться. Автор зміни коду/harness не є її незалежним reviewer. Автор пакета не приймає власний пакет.

Пакет готується паралельно перевіркам, але лишається DRAFT до потрібних результатів і незалежної перевірки складу. Наявні успішні результати використовуються з їхніми точними source bindings; через пакування їх не запускають знову. FAIL, обов'язкові skipped/NOT_RUN, відкриті findings або неспівпадіння source блокують READY. Scoped прийняття не стає повною готовністю продукту.

Пакет містить: package_id, owner, існуючі card IDs, base commit, точний commit або diff/source hash, allowlist, target, manifest з SHA256 файлів, QA/raw та reviewer verdicts, залежності, відомі обмеження, зміни схеми за наявності, порядок застосування, дозволену адресну перевірку та спосіб зберегти попередній стан при відмові. Небезпечні rollback/upgrade цим не дозволені. Секретів, реальних даних і mutable CURRENT-файлів як єдиного доказу в пакеті немає; для змінних індексів зберігати точний dated snapshot.

Root перевіряє source, target, незалежний verdict та чинний допуск і записує package_id, manifest SHA256, рішення APPROVED_LOCAL_INTEGRATION / RETURNED / HOLD, точну мету й UTC. Він не стає штатним QA чи автором пакета. Якщо є нова зміна, суперечність або конкретне питання, призначає адресну перевірку. Зміна значущих байтів/source/target означає новий пакет і відповідне нове рішення.

Після рішення лише єдиний призначений інтегратор перевіряє фактичний target/base/власників та застосовує саме погоджені байти. Drift, dirty-конфлікт чи активне чуже володіння зупиняють застосування без reset. Квитанція містить before/after source, фактичний результат і дозволені адресні перевірки. APPROVED, APPLIED і продуктова готовність — різні стани. Canonical STATE/QUEUE/PR змінює лише поточний уповноважений writer.

Чотири слоти загалом: root і до3активних виконавців. QA/reviewer/пакування займають слоти за залежностями; різні ролі можуть використовувати наявних агентів у різний час, з перевіркою незалежності для кожного артефакту. Власник наступним прямим порученням дозволив один постійний чат «БОС — качество и релизы». Його перевірений ID та копія: C:/Users/user/AppData/Local/BOSDev/quality-thread-creation.json. Він веде QA/пакування, з незалежним reviewer конкретного артефакту; нових дублів чи таймерів не створює. TOML лише описує роль, а не фактичний запущений процес/дозвіл.

Фактичні призначення головний підтверджує окремо, не дублюючи активних власників. На базі598143 поточний профайлер веде document_server_adapter, його reviewer — browser_evidence_check, спільний інтегратор — product_integration_continuation. Новий чат приймає наступні передані QA/пакувальні картки лише після розподілу root; original writer може допомагати з окремою документаційною частиною, не дублюючи власника пакета. Незакомічений network source030103 і дві невдалі browser-спроби не прийняті цим документом.

Усі власники звітують за [REPORTING_UA.md](REPORTING_UA.md), зберігаючи авторство й окремий незалежний verdict. Передача через існуючий ledger не означає виконання та не потребує відповіді-ехо. Збережено P05/A09/A10/A11, ERP mutex, широке external ownership, 11 GATES, синтетичні дані, TECHNICAL_READY=false та PILOT_ALLOWED=false. Локальне рішення не дозволяє production, main merge, paid API, activation/upgrade/rollback або нові вичерпані full/PG/E2E запуски.
