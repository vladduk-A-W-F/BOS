## Как берётся работа

1. Прочитать новое поручение/результат и точный срок. Если срок истёк, не назначать и не интегрировать изменения.
2. Проверить приоритеты по порядку: актуальная локальная версия; светлое превью; три кейса; вход и сохранение обучения; другие согласованные улучшения. Следующий приоритет доступен после готовности предыдущего либо явного blocker с причиной и владельцем решения.
3. Взять только готовую разрешённую карточку. До назначения заполнить owner, reviewer, source_commit, workspace, allowlist, зависимости, критерий завершения, допуск/класс проверки, остаток исторического лимита и следующий шаг. Нет предметного дефекта или feedback: новую карточку для занятости не создавать.
4. Проверить активных исполнителей. До четырёх одновременно; каждый автор в отдельной копии. Общий frontend, models/migrations и command/confirm имеют одного владельца в момент изменения. Root не выдаёт одну задачу двум авторам.
5. Автор возвращает diff, точный source/hash, объяснение поведения, ограничения и предложенный адресный oracle. Независимый reviewer получает сам diff и raw evidence. Автор не принимает свой код или тест.
6. QA выполняет только заранее рассмотренную адресную команду, после классификации NEW/SAME-PROBLEM и проверки допуска/лимита. Один успешный запуск не повторяется без новой причины. Провал фиксируется, повтор не автоматический. Сборка, source-проверка, браузер и пользовательская приёмка являются разными уровнями.
7. Root проверяет verdict, allowlist, совпадение исходника и доказательств; интегрирует один атомарный commit без amend. Затем обновляет карточку и PR, синхронизирует внешний пакет и передаёт следующий действительно готовый шаг.
8. Существенный результат по приоритетам 1–4 сопровождается авторским отчётом и независимым review; без них статус частичный. Контролёру передаётся один новый результат с постоянным message-id через существующий ledger; ACK не вызывает ответного эха.

## Роли

| Роль | За что отвечает | Чего не делает |
| --- | --- | --- |
| Root | Порядок, допуски, source pins, последовательная интеграция, PR, сроки | Не подменяет результат активностью и не снимает чужие ограничения |
| Диагностика / архитектура | Конкретная причина и минимальный контракт | Не вводит новый framework, shared DB или произвольный backlog |
| UX / контент | Понятный сценарий, реальные единицы, desktop/mobile | Не объявляет CSS просмотр браузерной приёмкой |
| Автор | Узкая реализация в выделенной копии | Не пишет canonical и не принимает собственный результат |
| QA | Разрешённая адресная проверка с raw output/exit/source | Не повторяет исчерпанные наборы и не правит тест ради PASS |
| Reviewer | Независимые findings/verdict по точным байтам | Не является автором проверяемого изменения |
| Упаковка | Неизменный manifest, версия, состав поставки | Не считает пакет фактической доставкой |
| Контролёр | Проверяет результат, риск даты и остаток | Не становится вторым интегратором |
