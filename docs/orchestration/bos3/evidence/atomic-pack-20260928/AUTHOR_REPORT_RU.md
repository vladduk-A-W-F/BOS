## Чесні межі

PDF-брошура лишається існуючою пам’яткою dev.7: repair receipt не змінює її
навчальні сценарії. Вона не є доказом dev.9, доставки або живої runtime.
Після невдалого вікна доставки dev.8 фактична доступність runtime
`UNCONFIRMED`; історичний запис dev.7 не дорівнює доказу поточного процесу.

`TECHNICAL_READY=false`, `PILOT_ALLOWED=false`; це не release `3.0.0` і не
production-дозвіл. Ліміти проблеми зберігаються: попереднє failed start є
`1/1` для window, а консервативний same-problem облік receipt-repair — `2/3`.
