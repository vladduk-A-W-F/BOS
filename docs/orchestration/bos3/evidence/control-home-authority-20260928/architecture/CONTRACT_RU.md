## Выбранная совместимость

После сохранения исходного каталога C leaf `BOSDev` заменяется одной directory junction на точный D target. Старые литералы C, LOCALAPPDATA/BOSDev и новые D callers получают один физический каталог, один `.queue.lock`, один `codex-channel-delivery.json`. Исправленные wrappers передают D явно и загружают одни и те же tools.

Альтернатива с redirect JSON недостаточна: старые скрипты напрямую формируют C пути и не читают redirect. Простое обновление известных callers также не доказывает отсутствие старого писателя. Junction минимально сохраняет эту совместимость, но не исправляет уже открытые handles, импортированные модули, закэшированные resolved paths или отдельно скопированные старые tools. Поэтому карта callers и полная quiescence обязательны. Если реальный filesystem/runtime запрещает проверяемую junction, переключение блокируется; символическая ссылка другого вида, policy bypass или частичный redirect не подставляются автоматически.

Сохранённый C архив содержит исходные байты, включая tools, backups и receipts; его нельзя выбирать как home или использовать для дальнейшей координации. Исходный путь C после переключения является alias. Если под «сохранить C» требуется оставить обычный активный каталог по прежнему адресу, эта схема неприменима: два независимых writable state set запрещены.

## Authority и публичный интерфейс

Минимум новых сущностей: один фиксированный JSON anchor и evidence receipt. Отдельный сервис, реестр, глобальная переменная окружения, новый storage framework и production test switch не требуются. Схема полей и ownership приведена в INTERFACE.json.

`resolve_control_home(value=None) -> pathlib.Path` сохраняется. `None`, точное имя C и точное имя D возвращают один абсолютный D Path только при ACTIVE anchor, корректной junction C -> D, ожидаемой физической идентичности D root/lock и наличии полного state set. Любой другой home, неизвестная версия, отсутствие/повреждение anchor, PREPARED/SUSPENDED, отсутствующий ledger или неоднозначный alias означают ControlHomeError до создания каталога, lock, state file или AppTools. Нет fallback на обычный C при отсутствии anchor. Импорт модуля не читает authority/state и не вызывает `.resolve()` для констант.

До `.resolve()` проверяется исходное имя: разрешены только абсолютные обычные drive paths C/D с нормализацией separator, регистра и завершающего separator; `..`, UNC, device namespace, ADS, дополнительные aliases и относительные пути отклоняются. Другая junction, которая случайно разрешается в D, не становится разрешённым именем.

Для D root, anchor и всех родителей до drive root запрещены reparse points. Исключение ровно одно: C leaf, тип directory junction, final target точно D. Для state files, lock и загружаемых tools запрещены reparse points и неожиданные hard links. `resolve()`/строковый prefix сами по себе недостаточны: сравниваются native file identity (volume/file ID; fail closed если платформа не даёт надёжную идентичность), типы и containment. Источники, файлы внутри backups и ACL проверяет root при snapshot preflight; неожиданный reparse/hardlink останавливает копирование, его не разыменовывают молча.

Resolver проверяет anchor и базовую целостность без изменения файлов. Проверка content hashes snapshot выполняется при establishment, а не при каждом штатном изменении queue/observer/ledger. После активации state законно меняется; исходные hashes являются доказательством переноса, не вечным runtime pin. Immutable generation, paths, root identity и lock identity должны сохраняться. Anchor не является защитой от злонамеренного администратора или другого процесса с правом подменять его: контракт опирается на проверенные ownership/ACL и остановку согласованных писателей.

`state_lock(home, timeout=10)` принимает resolved D либо разрешённое compatibility имя C, проводит его через тот же resolver, повторно проверяет authority перед открытием и после захвата блокировки, открывает существующий D `.queue.lock` в `r+b`, не создаёт и не удаляет его. Проверяет fstat(handle) против identity из anchor и доступных C/D имён. При изменении generation/phase/identity освобождает handle и отказывает. В обычной работе lock file никогда не заменяется. Lock на C архиве не участвует в активной координации. Между validated resolve и lock не строится новый independent home. Прямая `initialize()` после активации не восстанавливает отсутствующие config/queue: missing state есть отказ, init может только подтвердить уже существующий комплект без записи.

`deliver(target, prompt, message_id, home=HOME_DIR, *, model=None, thinking=None)` сохраняет target-first API; HOME_DIR становится литералом D. Обе ветки `ledger missing -> {messages:{}}` удаляются. Ledger должен существовать, иметь schema=1/messages object; существующие ACKNOWLEDGED/SENDING/UNCONFIRMED и unknown legacy records сохраняются без переинтерпретации. Критичные поля реально используемой записи валидируются до отправки. Существующее поведение idempotency/uncertainty/model сохраняется.

Public send и CLI send сначала разрешают home, проверяют target/self, обязательные аргументы и payload/model validation, затем создают AppTools. Текущий public guard 371a не является доказательством CLI ordering: CLI конструирует AppTools раньше target/self validation, это отдельное закрываемое место. Status читает observer под тем же lock. `doctor/read/mcp` не меняют своей transport-специфики, но явно переданный `--home` обязательно валидируется до side effects. `_deliver_resolved` остаётся private; lock/ledger проверки в нём не ослабляются.

## Порядок переключения

1. Независимый reviewer принимает design, точные diff двух пакетов и source hashes. Root собирает bounded QA card, сверяет исторический счётчик попыток по проблемам и снимает только разрешённые проверки на synthetic fixtures. Старые flow/wrappers pins не считаются принятыми с новым core.
2. Независимый migration reviewer получает новый core+consumers, raw QA, карту callers, точный root command sheet и перечень prerequisites. Только после статической приёмки этих материалов root готовит операционное окно; разрешение владельца уже есть, повторного общего вопроса не требуется.
3. До snapshot root прекращает все записи через control channel, observer, queue и самих root/worker; heartbeat `automation` останавливает через native automation tool с подтверждением результата и сохранением прежних полей. Остальные обнаруженные schedules/autostart/manual writers получают проверяемый stop/quiescence. Уже начавшиеся send, refresh и subprocess должны завершиться; захват `.queue.lock` сам по себе этого не доказывает, поскольку transport выполняется вне него. Не посылать контрольные handoff/ack через мигрируемый ledger после freeze.
4. Root фиксирует quiescence evidence вне control home. Прочитать live state для копирования можно только в этом отдельно проверенном операционном шаге. Проверить исходное дерево и ACL, целевые родители, свободный ресурс по разрешённой проверке, отсутствие target/archive/anchor, отсутствие неизвестных writers. Snapshot под старым lock: полный каталог C, opaque backups/receipts, размеры/hashes/metadata; данные не выводить в чат. Не сбрасывать ledger, observer, queue или состояния сообщений. Наличие SENDING/UNCONFIRMED не лечится переносом.
5. Создать PREPARED anchor; копировать полный frozen C комплект в ранее отсутствующий D target, исключая активный lock handle как объект переноса. Создать один новый постоянный D `.queue.lock` с одним нулевым байтом: только establishment создаёт его. Исторические lock bytes в C архиве сохраняются. Установить reviewed tools в D и reviewed setup consumers, сохранив прежние setup files. Проверить все byte hashes; различия допустимы только для точно перечисленных overlay files и нового lock identity. Копирование с cross-volume move, удалением источника или mirror-delete не допускается.
6. Закрыть snapshot handles после проверки, сохраняя внешний запрет всех writers. На C выполнить same-volume rename исходного каталога в точный архив, затем создать junction старого имени на D. При ошибке остановиться без повторов, записать фазу; не запускать tools для ремонта. Проверить junction/native final path, identity root и `.queue.lock` по C и D, оба указателя ledger на один D файл. Само создание alias не есть активация. Старый код не должен запускаться в этом промежутке.
7. Root сохраняет immutable prepared receipt: hashes snapshot и overlays, identities, C backup, quiescence, manifest SHA, attempt accounting, command exit codes. Независимый reviewer сверяет установленные bytes и raw evidence и выдаёт конкретный `ACCEPT_MIGRATION_COMMIT` на exact generation/receipt hash. При отсутствующем доказательстве ACTIVE запрещён.
8. Root атомарно заменяет PREPARED anchor на ACTIVE через temp file в том же D parent, flush/fsync и replace. Это единственная логическая точка переключения. Anchor включает hash принятой prepared receipt и reviewer evidence, identities D root и lock. Все writers ещё остановлены. Перечитать anchor; системный crash/power loss не считать автоматически восстановленным: uncertain receipt требует проверки, без fallback.
9. Разрешённая ограниченная верификация на месте подтверждает resolver C/D/default -> D, один lock/ledger, сохранение snapshot, работу read-only coordinator status. Не делать настоящую пробную отправку, app launch, PG start, startup-wrapper run или изменение policy. Независимый reviewer принимает final receipt со scope `CONTROL_HOME_INSTALLED`, без runtime readiness. Только после этого root возобновляет те writers/schedules, чьи runtime и policy условия отдельно выполнены; заблокированный C64 route остаётся заблокированным.

## Сбой и восстановление

До ACTIVE нет D authority. Писатели остаются остановлены. Неполный D комплект и PREPARED anchor сохраняются как evidence, не удаляются для автоматической повторной попытки. Возможен отдельно рассмотренный возврат к исходным C байтам: только после доказательства отсутствия D writers, удаления именно проверенной junction без recursive traversal, восстановления точного C имени и прежних setup files. Это не штатный автоматический rollback и не разрешение обойти A10.

После ACTIVE D является единственным источником состояния, даже если последующая проверка или запись final receipt не удалась. Нельзя вернуть старую C копию или слить журналы эвристически. При проблеме остановить writers, перевести anchor в SUSPENDED по проверенному recovery step и исправлять D вперёд. При неопределённости после replace сначала установить фактически сохранённый anchor/generation и историю writes. Исторический запрет activation/upgrade/rollback и отдельные Windows policy условия сохраняются; этот контракт не даёт общего product rollback разрешения.

PowerShell wrapper parsing может быть статическим; заблокированный execution route не запускается другим shell.
