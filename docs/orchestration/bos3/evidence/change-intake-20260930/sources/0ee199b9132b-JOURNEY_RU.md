## Перший екран і загальний моніторинг

**Порядок:** онлайн-брошура → вибір бізнес-завдання → персональний вхід → верхня панель «Загальний моніторинг» → навчальний сценарій → перевірний результат → передача до CRM.

**Є в поточному джерелі.** Онлайн-брошура вже стоїть перед входом у навчальному та звичайному неавторизованому маршруті. Вона має шість сторінок, індикатор прогресу, ручне гортання кнопками, клавішами та свайпом, інтерактивну схему, передачі між відділами, графік початкового стану й три картки кейсів. Обраний `?training=slug` зберігається під час переходу до входу. Після входу «Загальний моніторинг» уже розміщено під верхньою навігацією та над робочою областю. Показники читаються зі знімка ERP; для них розкриваються джерело, спосіб обчислення, охоплення, бізнес-дата й час читання. Це висновки з коду, а не браузерне підтвердження. [HTML:5372–5459, 5735–5743, 5753–5787; CSS:682–713; HTML:5171–5205, 5284–5315]

**Пропозиція візуального шару.** Під заголовком «BoS — рішення під ваш бізнес» показати три прикладні завдання вже на першій сторінці брошури, не прибираючи саму брошуру та можливість перегорнути всі сторінки. Той самий номер і колір кроку мають вести від картки завдання до навчальної сесії; після входу слід чітко показати «Продовжити обраний кейс». Поточний крок, відповідальний відділ і очікуваний результат залишаються на видноті. Документи, розрахунок, джерела та історію відкривати за запитом. Верхній моніторинг показує **робоче читання ERP**, а графік брошури лишається позначеним **«Навчальний приклад»**; не зображати його як live-показник підприємства. Анімація має підкреслювати передачу між перевіреними кроками, не створюючи враження вже проведеної операції. У CSS уже є плавна поява сторінки та рух лінії схеми; `prefers-reduced-motion` вимикає рух. [HTML:5409–5451; CSS:157, 682–710]

Пропонована українська мікрокопія: «Гортайте огляд або відразу оберіть задачу», «Продовжити обраний кейс», «Джерело показника», «Останнє успішне читання», «Підготувати передачу до CRM». Для помилки: «Дані не оновлено. Повторіть читання»; для порожнього результату: «Доступних записів немає».

## Передача до CRM та стани

**Є в поточному джерелі.** Frontend передає `session_id` і `case_id` обраного навчального кейсу до CRM handoff. Сервер готує чернетку з доступних джерел; створення вимагає preview та явного підтвердження. Для вже наявної передачі інтерфейс пропонує відкрити відповідну угоду без дубля. Це **не доводить** точну тотожність усіх бізнес-сутностей між брошурою, сесією, ERP та CRM: її потрібно звірити з окремим ID-контрактом. Не виводити customer/order/invoice ID зі `slug` або `case_id`. Контакт не є оплатою, готовність — відвантаженням. [HTML:5482–5499, 5507–5522, 5753–5787; identity map SHA-256 `91237e09cce96aa8927470455b0f50995caa5a72f4a0c77fcc44199adbf49a00`]

**Пропозиція станів.** Для `loading/refreshing` показувати очікування й не видавати старе значення за нове; для `empty` — порожній результат і допустимий наступний крок; для `error/stale/denied/context-drift` — причину та ручне оновлення без активного переходу до джерела; для `fresh` — показник, джерело й дозволений ролі перехід. Навчальна сесія має розрізняти `not_started`, `in_progress`, `completed` та помилку. Передача до CRM: «перевірка → чернетка → preview → явне підтвердження → квитанція» або «вже існує». Поточна реалізація моніторингу вже приховує значення без успішного читання та зберігає час останнього успішного читання у вікні. [HTML:5171–5205, 5220–5265, 5477–5499, 5507–5522]
