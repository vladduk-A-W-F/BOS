BoS — єдиний порядок приймання змін
Підстава: пряме доручення власника 30.09.2026 про синхронізацію, систематизацію і приймання.

Чинна роль: sole integrator 01a0dd56-ca2d-79c0-b159-bde80074a026 залишається єдиним редактором canonical/code/PR. Контролер зводить факти; main координує власників; quality і окремі reviewers перевіряють незалежно. Реєстр не замінює продуктову QUEUE і не створює claims.

Запит має містити існуючу картку, автора, точний source та candidate hash, ціль застосування, окремий allowlist, завершені залежності, незалежний verdict, дозволені перевірки і критерій готовності. Без цих даних — REGISTERED/NEEDS_INPUT, а не READY.

Стани розділені:
1. REGISTERED — запит зафіксований, ще не прийнятий.
2. IN_REVIEW — reviewer перевіряє точні входи.
3. RETURNED — потрібні адресні виправлення; початкові байти й зауваження зберігаються.
4. APPROVED_SCOPE — конкретний пакет прийнятий лише у названому обсязі.
5. APPLIED — є before/after, квитанція та перевірка фактичного цільового дерева.
6. PUBLISHED — GitHub має точний коміт; стан PR фіксується окремо.
7. DELIVERED — перевірено саме запущену версію. Commit чи HTTP окремо не підтверджують усі бізнес-сценарії.

Один пакет визначається карткою, candidate hash і ціллю. Дублі посилаються на первинний запис. Змінена версія є новою revision цього запиту; новий ID не обнуляє ліміти перевірок. Для незмінених прийнятих байтів достатньо порівняння hashes; змістовні delta перевіряє незалежний reviewer.

Пріоритет: конкретні зауваження, що блокують чинну картку; готові перевірені пакети для послідовного застосування; незалежна незаблокована підготовка. Старі mergeable PR та зелений службовий CI не є підставою автоматичного merge.

Поточний REGISTRY_DRAFT/наступний перевірений REGISTRY — знімок фактичних доказів. Старі snapshots не редагуються; нові disposition мають своє evidence і час. CURRENT є вказівником на актуальний прийнятий реєстр, а не новим доказом для старого пакета.

Публікація й належність гілки: поточна гілка codex/bos3-prerelease-20260927, PR10. PR9 є кандидатом на закриття як поглинутий історією PR10, без видалення гілки й без нового main merge. Перед зміною PR інтегратор повторно звіряє refs. PR10 залишається draft/hold до належних умов приймання.

Оновлення виконуються за новим результатом у чинному циклі та через ledger. Додаткових чатів, daemon чи таймерів немає. Статуси/хеші/індекс — без нового модельного завдання; змістовні правки — відповідному власнику; автор не є reviewer.
