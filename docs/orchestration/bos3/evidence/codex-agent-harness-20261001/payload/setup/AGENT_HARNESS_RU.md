# BoS: агентский харнесс Codex

Область: работа агентов Codex. Этот документ не меняет тестовый харнесс продукта, полномочия на запуск, установку, миграцию или приёмку BoS.

## Управление и рабочая копия

Текущий единственный интегратор: alias `integrator`, чат `01a0dd56-ca2d-79c0-b159-bde80074a026`, рабочая копия `D:/3/BOSDev/workspaces/bos3-canonical/repo`. Его точное назначение сверяется с `docs/orchestration/bos3/CONTROL_STATE.json`. Канал `main` сохраняет исторический адрес, не заменяет текущего интегратора. Старые лабораторные копии и `config.sync_source` не переключаются автоматически.

Действующая последовательность: точная карточка и исходник → исполнитель в отдельной копии → разрешённая проверка → независимый reviewer → решение интегратора → последовательное применение → фактический результат. Автор кода не принимает собственную работу.

## Команды

```powershell
. 'D:/3/BOSDev/setup/use-d-drive.ps1'
& 'D:/3/BOSDev/setup/bos-flow.ps1' refresh
& 'D:/3/BOSDev/setup/bos-flow.ps1' status
& 'D:/3/BOSDev/setup/bos-flow.ps1' next
& 'D:/3/BOSDev/setup/bos-flow.ps1' models
```

`refresh` один раз запрашивает текущие состояния шести обозначенных рабочих чатов, включая integrator и enablement. Отсутствующий ответ запрашивается отдельно один раз. `status` и `next` читают сохранённый индекс, не будят агентов. Поле `checked_at_utc` относится только к наблюдению статуса. Назначение и результат остаются историческими записями observer: их время и provenance показаны отдельно, а свежий статус не подтверждает их текущую актуальность.

Короткий вывод сохраняет отдельно исторические runtime/working/lab версии, публикацию документации и принятый пакет статических архивов; он не пересылает вложенную историю кандидата. Head документации и открытый PR не доказывают исполняемую интеграцию, готовность продукта или доставленный runtime. Подробные поля остаются в `D:/3/BOSDev/reports/local_flow/CURRENT.json` и исходном observer; сокращение вывода их не удаляет.

- `active`: идёт ход, продвижение ещё нужно подтвердить результатом.
- `idle/completed`: ход завершён; это само по себе не разрешение назначить новую работу.
- `notLoaded`: чат не загружен; он не считается свободным исполнителем.
- `unknown` или ошибка: достоверного текущего состояния нет; прошлый результат сохраняется как история.

Для адресной передачи используйте `bos-flow.ps1 handoff -Packet PATH` для проверки и затем `-Execute` для одной доставки. Координация и результаты для текущего проекта адресуются `integrator`; обратный отчёт — `observer`. В пакете нужны точный источник и проверяемые ссылки с SHA256. Отправка проходит через существующий `codex_channel.py` и ledger. `ACKNOWLEDGED` подтверждает доставку, не выполнение. Для `UNCONFIRMED` сначала сверить адресата, не создавать новый ID для повторной отправки.

Путь `kind=assignment` в старом flow остаётся legacy и не получает новых полномочий на очередь BoS 3.0. Продуктовые задания BoS 3.0 выдаёт текущий root штатным субагентам по актуальным карточкам. Добавление integrator в наблюдение и адресатов не снимает широкую резервацию файлов и не разрешает конкурентную запись.

## Модели и параллельность

Источник конфигурации: `.codex/config.toml` и `.codex/agents/*.toml` канонической копии; правила передачи — `D:/3/BOSDev/plans/FLOW_POLICY.json`.

| Работа | Профиль |
|---|---|
| Статусы, хеши, точное сравнение, неизменные результаты | Обычная команда без модели |
| Короткая содержательная подготовка | gpt-6-luna / medium |
| Ограниченная реализация, UX, разрешённая QA | gpt-6-sol / medium |
| Независимая ограниченная проверка | gpt-6-sol / high |
| Архитектура, миграция, права, сложное решение | gpt-6-astra / high |
| Действующий главный | inherit |

Обычно два независимых исполнителя и один резервный слот review, максимум три субагента плюс root. Независимость требует свободного фактического слота, завершённых зависимостей, отдельных копий и непересекающихся файлов. Интеграция и ERP-записи остаются последовательными.

Настройки действуют для новых назначений. Работающий чат не переключается ради экономии. Запрошенная модель и подтверждённая фактическая модель учитываются отдельно. Если каталог ролей текущей сессии старый, использовать поддерживаемые явные `model`/`reasoning_effort` с коротким самостоятельным заданием, не объявлять старую сессию перезагруженной.

Отчёт сохраняет авторство, exact source/diff, raw результаты и exit codes, FAIL/NOT_RUN, независимый verdict, blocker и следующий шаг. Шаблон: `D:/3/BOSDev/reports/REPORT_TEMPLATE.json`. Отсутствующий результат не заменяется PASS. Не передавать старые полные логи: до пяти ссылок с хешами и краткое резюме.

## Границы эксплуатации

Новых чатов, планировщиков или второго app-server не создаётся. Используется существующая automation. Обновлённая обвязка не меняет её расписание и не запускает модели ради простоя. Реагировать на новый результат, blocker или поручение, не на квитанцию доставки.

Control-home пока расположен на C; его единственная блокировка и ledger сохраняются. Исходник установщика на D принят отдельно, фактический перенос ещё не доказан. При будущем переносе включить эту правку в свежую сверку потребителей и baseline; старые принятые архивы не переписывать.

Проверка этой настройки — новые синтетические проверки маршрутизации, статусов и отсутствия побочных действий. Это не QA продукта и не повтор старых full/PG/browser/native проверок.

Официальные основания параметров Codex: [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Проектная конфигурация проверена по файлам; изменение runtime-модели уже работающего агента из этого не следует.


# Явное назначение в выгруженный чат

Основание: прямое поручение владельца 30.09 настроить все существующие чаты, роли, модель под задачу и продолжить BoS по плану. Это узкое изменение поведения агентского канала, а не сброс лимитов продуктовых проверок.

notLoaded по-прежнему не считается автоматически свободным исполнителем в status/next и не создаёт claim. Для уже явно назначенной main/integrator карточки допускается новый вызов с моделью только если свежий одиночный native wait_threads сообщает одновременно: точный target/local, notLoaded, существующий completed ход без ошибки, и положительное wake.reason=inactiveStatus для того же target/local. Активные флаги, ошибки, отсутствующий ход, неизвестное состояние и несовпадение identity остаются отказом. В ledger записывается фактический notLoaded и eligibility=dormant_completed, не выдуманный idle.

Сохранены preflight до резервирования, повторная проверка ledger под lock, SENDING до отправки, запрет повторов UNCONFIRMED и запрет дублей. Между отдельным native poll и отправкой остаётся прежнее окно изменения состояния: атомарного compare-and-send API здесь нет. Поэтому новое назначение координируется одним владельцем, runtime-модель не объявляется подтверждённой по запрошенному профилю.

Проверка — только новый ограниченный mocked preflight/ledger regression через извлечённые функции, без импорта live tools, сети, настоящих сообщений, подмены CODEX_THREAD_ID процесса или записей живого ledger. Перед применением нужны независимый review exact bytes и сохранение live before-hash. Старые full/harness suites и app/PG/browser tests не запускаются.
