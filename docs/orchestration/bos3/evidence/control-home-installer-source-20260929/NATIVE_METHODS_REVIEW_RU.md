## Identity И Типы

1. До resolve/open/copy проверять lexical absolute local paths, фиксированные roots и все ancestors; запретить UNC/device/ADS input paths, dotdot и неразрешенные aliases. `CreateFileW(OPEN_EXISTING)` с `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT` позволяет инспектировать directory/reparse leaf без следования ему. Это не отменяет проверки родителей. `CREATE_NEW` предназначен для отсутствующих output files; `OPEN_ALWAYS`/`CREATE_ALWAYS` не подходят для fail-closed существующего state. [Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).
2. Handle identity получает `GetFileInformationByHandle`; сохранять одновременно attrs, link count, size и volume/file index. Сравнивать identity прочитанного handle с проверяемым path до и после операции, пока действует внешняя quiescence; просто `Path.resolve()` не доказывает отсутствие замены. [Microsoft GetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle).
3. Формат текущего core строго **volume serial 8 lowercase hex + 64-bit index 16 lowercase hex**, см. [bos_dev.py:122](D:/3/BOSDev/qa-scratch/bos3-control-home-install-20260928/source/staged/bos_dev.py:122). `FileIdInfo`/128-bit ID нельзя подставить в anchor без изменения принятого core. Для ReFS 64-bit uniqueness не гарантирована; источник и приемник должны пройти будущий разрешенный supported-local-filesystem gate, консервативно NTFS. Никакого probe сейчас. [BY_HANDLE_FILE_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information).
4. Все обычные files source, backups, overlays, receipts и lock: regular, non-reparse, link count=1. Для directories проверять тип, attrs и identity; не переносить file-link-count правило на directory без основания. Единственное намеренно разрешенное reparse после alias: точное старое C имя с mount-point tag к exact D home. Любой иной reparse/type/unsupported feature останавливает фазу; не следовать ему и не пропускать.

Native declarations должны задавать явные argtypes/restype: HANDLE/pointers pointer-sized, DWORD/BOOL/ULONG Windows widths, корректное выравнивание структур. BOOL APIs: zero failure + сохраненный GetLastError; GetSecurityInfo/SetSecurityInfo возвращают DWORD status непосредственно. Каждый handle/buffer имеет одного владельца и finally cleanup. Исключение не заменяется пустой identity/ACL или false PASS.

## Byte Lock И Opaque Snapshot

Snapshot открывает **существующий** C `.queue.lock` без create/truncate, сверяет single-link identity/размер, удерживает byte 0 и повторно сверяет identity. Он не импортирует новый D resolver до ACTIVE. Для native пути допустим `LockFileEx` exclusive+fail-immediately с конечным timeout и парным unlock того же диапазона; msvcrt-путь должен сохранять тот же byte contract. Межпроцессная совместимость требует отдельного разрешенного native QA, которого сейчас нет.

**Locked byte читать/хешировать через owning handle.** Microsoft прямо указывает: второй handle даже того же процесса не получает доступ к эксклюзивно заблокированной области. Обычный повторный `read_bytes`/CopyFile для `.queue.lock` под snapshot lock может отказать. Не отпускать lock ради обхода; отдельно сохранить его bytes через owning handle. Перед alias закрыть snapshot handles только при сохраняемом внешнем freeze. [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex).

Snapshot manifest покрывает полное дерево, включая opaque/history/backups/tools, relative path, type, size/hash, identity, attrs и security evidence. Не разбирать/пересоздавать ledger как новую пустую структуру. JSON validation необходимых envelopes не дает права отбрасывать неизвестные записи. Source manifest перепроверяется после копирования/перед alias; partial enumeration или hash error не считается полным snapshot.

Обычный `shutil.copy/copy2` на Windows не сохраняет owner/ACL/alternate streams и не может быть единственным переносчиком security/opaque data. [Python shutil](https://docs.python.org/3/library/shutil.html). Для неподдерживаемых ADS/EFS/compression/других значимых features нужны явное сохранение с readback или точный refusal до опасной фазы, не молчаливая потеря. Named streams возможны и у directories; будущая ограниченная проверка `FindFirstStreamW/FindNextStreamW` должна отличать конец enumeration от ошибки. Если реализация не копирует ADS, обнаружение любого дополнительного stream закрывает gate. [Microsoft FindFirstStreamW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirststreamw).

`CopyFileW(..., TRUE)` может быть native компонентом для отсутствующего файла, но не заменяет type/identity/ACL/stream readback: он следует source symlink, поэтому предварительный запрет reparse обязателен. Source/target hash+размер и все заявленные metadata проверяются отдельно. [Microsoft CopyFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-copyfilew).

## Owner, Group, DACL

Минимальная обязательная native security модель:

- Source handle запрашивает READ_CONTROL; `GetSecurityInfo(SE_FILE_OBJECT, OWNER|GROUP|DACL)` возвращает owner SID, primary group SID, DACL и allocation security descriptor. Скопировать нужные данные, пока allocation жив; `LocalFree` только возвращенного whole descriptor, не внутренних SID/ACL pointers. Проверить status и валидность всех компонентов. [GetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo).
- DACL presence и pointer различать: missing/NULL DACL не эквивалентны пустому ACL. Не превращать decode/read error в NULL DACL. Для данного приватного state null/missing security надо отвергать, не расширять доступ. [GetSecurityDescriptorDacl](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptordacl).
- Сохранять owner/group SID, ordered ACE content/masks/flags и существенные DACL control bits, особенно protected/inheritance. Control извлекается через `GetSecurityDescriptorControl`, не определяется по догадке о parent. В private evidence можно хранить O/G/D SDDL плюс соответствующий control и digest; сравнение не должно сортировать ACE и менять их смысл. [GetSecurityDescriptorControl](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorcontrol), [SDDL conversion](https://learn.microsoft.com/en-us/windows/win32/api/sddl/nf-sddl-convertsecuritydescriptortostringsecuritydescriptorw).
- `SetSecurityInfo` получает WRITE_OWNER/WRITE_DAC доступ по задаче и те же owner/group/DACL с явно выбранной защитой inheritance. Он может распространять inherited ACEs на children; финальная tree readback обязательна после всех parent changes. NULL DACL при установке дает полный доступ, потому запрещен. Нельзя молча назначать текущего пользователя вместо source owner или включать privileges/менять policy после access denied. [SetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo), [SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information).
- Новый target и private backup/evidence directories должны быть закрыты до записи secret bytes. `CreateDirectoryW` с явным SECURITY_ATTRIBUTES предпочтительнее широкого parent inheritance с последующим исправлением; сразу проверить security readback. Временная ограничительная DACL допускается только как staging защита, а не как скрытая подмена конечных source ACL. При невозможности конечного exact preservation остановиться до alias. [CreateDirectoryW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createdirectoryw).

Для overlays заменяется содержимое, не произвольно security policy: сохранять security проверенного destination файла или принятого эквивалентного C source, а не ACL scratch-разработчика. Новый D lock получает принятую security policy старого lock, но имеет намеренно новую identity. Archived C lock bytes/identity сохраняются. Owner/group/DACL не равны всем SACL/audit/MIC свойствам: не заявлять полное security preservation за пределами реально поддержанного и проверенного. Неожиданная неподдерживаемая security особенность требует blocker.

## Archive И Junction

**Archive**: только exact C source в exact отсутствующий C archive, same-volume без слияния и перезаписи. Native реализация `MoveFileExW(source, archive, 0)` соответствует rename без COPY_ALLOWED, REPLACE_EXISTING, DELAY_UNTIL_REBOOT. Проверить source/archive-parent native volume и отсутствие archive, закрыть мешающие handles под внешним freeze; после успеха archive root/lock identities должны совпасть с source snapshot, bytes/ACL сохранены. На отказе никакого copy/delete fallback. [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).

**Одна junction operation** после подтвержденного archive: создать отсутствующий C leaf directory с явно подходящей ACL; открыть его без follow; сформировать `IO_REPARSE_TAG_MOUNT_POINT` buffer и выполнить один `DeviceIoControl(FSCTL_SET_REPARSE_POINT)`. Не запускать cmd/mklink, PowerShell fallback, не менять privilege/policy и не повторять ошибку иным методом. Native API здесь является выбранной реализацией будущей отдельно разрешаемой операции, не обходом C64 или diagnostic запрета. Документация SET указывает требования privilege: их отсутствие означает failure, не право автоматически выдавать их процессу. [FSCTL_SET_REPARSE_POINT](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_set_reparse_point).

Buffer contract: tag `0xA0000003`; 8-byte common header; mount-point payload содержит четыре USHORT offset/length и UTF-16LE PathBuffer. Substitute name соответствует `\??\D:\3\BOSDev\control-home`, print name exact обычному D path. Offsets/lengths считаются в **байтах**, длины имен не включают NUL; buffer содержит terminators. ReparseDataLength включает mount-point payload, не общий header. Все границы длины проверяются и при GET readback. [REPARSE_DATA_BUFFER](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_reparse_data_buffer).

Readback должен подтвердить tag, exact substitute/print target, native followed C-root=D-root, C-lock=D-lock и ожидаемую D lock identity. Одного `is_dir`, `resolve` или GET tag мало. Partial creation оставляет архив, D и пустой/частичный C leaf как evidence; не удалять автоматически и не переименовывать архив назад. Прежняя таблица команд использовала оболочечную форму того же rename/junction; новая native реализация требует отдельного source/admission review, но не меняет authority design.

## Atomic Receipts И Anchor

Для каждого immutable receipt: подготовить exact bytes, exclusive temp в том же проверенном private parent, flush/fsync, публикация только при отсутствующем конечном имени, затем reopen/readback/hash/security check. Не публиковать частичный receipt и не переписывать принятый файл. Для anchor replace допустим existing exact PREPARED generation, ранее закрепленный hash/identity, private same-parent temp с нужной ACL и atomic replace. [Python os.replace](https://docs.python.org/3/library/os.html#os.replace).

Flush необходимо выполнять на file, а не на stdout/pipe. Нельзя выводить глобальную crash durability файловой системы или бесконечную гарантию из одного успешного flush/rename; native failure/unknown outcome должен оставлять состояние неопределенным до readback. Не открывать volumes ради blanket flush или resource probes. [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).

## MCP Config: Bytes И TOML

Будущий root отдельно получает реальные before bytes и заранее подготовленные reviewed after bytes приватного config. Установщик не синтезирует TOML через json.dump/общий writer. Admission связывает path, before/after hashes, размер, exact byte offset/span, old/new token bytes или их hashes, semantic key `mcp_servers.bos_control.args` и единственный индекс script аргумента. Before должна совпасть непосредственно перед backup и replace.

Обязательные проверки: после замены только одного заявленного span итог точно равен pre-reviewed after bytes; prefix/suffix, encoding/BOM и newline bytes остаются прежними. В будущей разрешенной фазе `tomllib` разбирает оба документа, проверяет ожидаемый old/new script и равенство всей semantic структуры кроме единственного args элемента, сохраняя command, остальные args, env, enabled_tools и прочие tables. TOML parser не пишет TOML и доступен в Python 3.11+; несовместимый интерпретатор или parse error закрывает gate, не разрешает ad-hoc regex fallback. В этой подготовке parser не исполняется. [Python tomllib](https://docs.python.org/3/library/tomllib.html).

Простой global replace старой строки недостаточен: она может встречаться в комментарии/другом server. Перед изменением точный byte backup с source security и readback, затем private same-parent replacement с сохранением destination ACL и after hash. Config change входит в PREPARE receipt до независимого commit acceptance, не после ACTIVE. Это не перезапуск MCP: source-stale worker остается запрещенным для state/send и допустим read-only лишь при отдельно доказанных capability/in-flight ограничениях.

## Admission И Quiescence

OPERATION_CONTRACT автора должен конкретно фиксировать следующие обязательные значения и exact schema, не принимать произвольный объект по одному boolean. Имена новых внутренних schemas выбирает автор согласованно; это не новая authority architecture.

| Документ | Минимальная проверяемая привязка |
| --- | --- |
| Per-phase admission | schema/version, operation+generation, exact phase, fixed paths, owner/native message reference и scope, installer/native-module/contract/dependency hashes, deadline, previous phase receipt path+hash, required independent review path+hash+verdict, maximum_invocations=1, no retry, required QA acceptance и исторический attempt accounting |
| Quiescence evidence | generation/freeze identity, observed_at/expires_at UTC, native source references+hashes, полный fixed actor/caller map, no pending write/transport, heartbeat ID+PAUSED native receipt, registrations/cached modules/direct callers disposition, root sole operator, no resume с момента freeze; неизвестный actor/capability=incomplete |
| Snapshot/prepare/alias receipts | generation/phase, predecessor hash, inputs/pins, frozen source manifest, source/archive native identities, root/lock IDs, ACL readback, exact opaque copy/overlay deltas, setup/config backup+before/after hashes, native calls/results, quiescence refs, one-shot marker, skips/blockers |
| Commit acceptance | минимум runtime-required verdict+generation+prepared_receipt_sha256, плюс независимый issuer/evidence binding; сам installer не выпускает ACCEPT_MIGRATION_COMMIT |
| Verify/final acceptance | persisted ACTIVE generation/hash/readback, C/D/default and root/lock identity evidence в отдельно допущенном verification scope, сохраненные bytes до resumption, blockers, independent final verdict, индивидуальная resume eligibility |

Freshness проверяется в каждой фазе и перед authority-changing шагом, после длительных операций повторно. Свежий JSON или lock acquisition не доказывает глобальную quiescence: необходимы реальные root-verified native источники. Installer валидирует переданные proofs, но не проводит скрытые process/registration/C64 probes для замены отсутствующего evidence. Source-completion request не выдает live execution authority. Проверка отсутствующих будущих документов должна завершать вызов до mutation; при наличии корректных документов фаза должна иметь полноценную реализацию.

## Фазы И Частичный Сбой

1. **snapshot**: validate admission/evidence/caps; exclusive per-phase started marker до мутаций; полный frozen C manifest под старым lock, включая безопасность и bytes. Никакого reset/empty ledger.
2. **prepare**: проверяемый предшественник; D отсутствует; закрытый новый D tree; opaque copy, новый стабильный lock, exact backup и accepted overlays/setup/config; PREPARED nonactive anchor и immutable stage receipt. Не считать совпадение hash доказательством ACL.
3. **alias**: поддержанный freeze, source snapshot неизменен, handles закрыты; один same-volume rename, один native junction, exact readback; final prepared receipt. Без auto-activate.
4. **activate**: свежая quiescence и независимый ACCEPT_MIGRATION_COMMIT на final prepared hash; еще раз проверить installed identities/config/bytes; replace только своего PREPARED anchor; persisted ACTIVE readback. Это единственный authority commit point.
5. **verify**: новая точная authorization на ограниченную installed verification; ничего не repair/reset/send/restart. Final reviewer acceptance остается отдельной. Нельзя автоматически запускать весь QA, wrapper, app или C64.

Started marker расходует конкретную фазовую попытку. Любая ошибка, timeout, lost receipt или неизвестный native result оставляет marker и остатки; не retry/reset/delete. До ACTIVE сохраняются PREPARED и original C archive, но partial setup/config overlays тоже фиксируются как уже возможные изменения. После ACTIVE D остается authority даже при receipt failure; только отдельно рассмотренный forward/SUSPENDED recovery, не stale-C fallback. Неизвестный commit нельзя классифицировать solely по исключению: нужен отдельный разрешенный persisted-anchor readback/reconciliation.
