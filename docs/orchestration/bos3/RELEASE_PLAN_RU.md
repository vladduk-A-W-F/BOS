# BoS 3.0: план и управление выпуском

Подготовлен 27.09.2026, Europe/Berlin. Реализация запущена 27.09.2026 по прямому поручению владельца «Запускай подготовленный план BoS 3.0 во всю силу». Первая передача теперь только владельцу на его ПК. Ранее выбранные 2–3 приглашённых пользователя подключаются лишь после отдельного решения о переносе и доступе. Исторические ограничения сохранены.

## Цели и границы

Уточнение владельца 27.09: главный результат предрелиза именно законченный путь «красивая одностраничная брошюра -> три отдельных кейса с передачами, исполнением, контролем и эффектом -> понятный вход в BoS 3.0». Полная доводка локализации и совместной работы всех отделов относится к последующему релизу после обратной связи. Текущие назначения, source pin и следующий исполнимый шаг: ACTIVE_WORK_PLAN_RU.md. Просмотр презентации не выдается за выполнение кейса; учебные эффекты не выдаются за результаты реальных клиентов.

- 04.10.2026: BoS 3.0.0-rc.1, закрытый аутентифицированный owner-review предрелиз полного пути «брошюра -> три независимых урока -> тур -> свободная учебная работа», включая минимальную CRM-вертикаль. Не production и не пилот с рабочими данными.
- 04–10.10: обратная связь и исправления выбранных дефектов; никакого скрытого расширения требований.
- 11.10.2026: принять готовый к выпуску код/тег BoS 3.0.0 только при фактической приёмке и выполнении необходимых gates; иначе остаётся rc с согласованным остатком и новой датой. Production activation не входит в это решение, требует отдельного разрешения и эксплуатационной приёмки.
- Даты являются целями, не обещанием. Новый ярлык версии не доказывает готовность. Production, реальные данные и shared-DB SaaS в этот план не входят.

## Управление

Единственный текущий интегратор: root чата «Подготовить план консолидации BoS», 01a0dd56-ca2d-79c0-b159-bde80074a026. Архивный координатор «БОС — главный оркестратор» получает план только для сверки непрерывности; он не запускает второй контур разработки.

| Направление | Ответственность | Передаваемый результат |
| --- | --- | --- |
| Продукт / UX | Путь первого и повторного посещения, мобильный UI, брошюра, тур | Карта экранов, тексты действий, критерии завершения |
| Контент / учебные данные | Завод, отделы, истории, документы, арифметика | Версионированный fixture-контракт и единый словарь |
| Архитектура / backend | Изоляция, права, команды, CRM, ссылки на ERP | Контракт, миграции, API, адресные доказательства |
| Frontend | Учебный маршрут, состояния, CRM UI | Patch существующего frontend и сценарии проверки |
| QA / evidence | Матрица требований, лимиты, raw output, traceability | Кандидат-специфичные результаты без ложного PASS |
| Security / release | Закрытый доступ, synthetic стенд, manifest, выдача кандидата | Проверенный target и инструкция доступа |
| Независимое ревью | Проверка чужого кода/пакета и рисков | Findings и отдельный verdict |
| Оркестратор | Приоритеты, назначения, зависимости, интеграция, сроки | Единый принятый кандидат и понятный отчёт |

Это рабочие роли, а не восемь постоянных процессов. Максимум четыре субагента одновременно, отдельные копии для изменений, один интегратор. Бизнес-отделы описаны отдельно в SCENARIOS_UA.md. После завершения карточки root выдает следующую готовую работу, не ожидая нового START. Фактические назначения и review-зависимости ведутся в ACTIVE_WORK_PLAN_RU.md.

4. INVITES: адреса/способ выдачи индивидуального доступа позже, приватно; ничего не отправлять автоматически. Владелец + 2–3 пользователя уже подтверждены.

## Контроль

По прямому поручению владельца продолжать активную реализацию существующая heartbeat automation id automation обновлена штатным инструментом 27.09: ACTIVE, интервал 15 минут, тот же чат. Она должна продвигать готовые разрешенные карточки и принимать результаты, а не только проверять метаданные. Это не обещание работы при выключенном ПК или закрытом приложении. При недоступности контроля фиксировать UNCONFIRMED, новый scheduler не создавать. Старые очереди не запускать; прежние продуктовые evidence неизменны.

Прямой START уже получен и повторно подтвержден поручением активного продолжения. Root берет следующую разрешенную работу из ACTIVE_WORK_PLAN_RU.md, назначает актуальный SHA/path, получает независимое review и интегрирует последовательно. JSON не является самостоятельным разрешением; отдельные исключения на исчерпанные проверки, browser и доставку действующего runtime требуют точного ответа владельца.

Повторяющиеся неизменные статусы не отправлять. Сообщать о принятом результате, провале, реальной угрозе сроку или необходимом решении. Delivery/active не равны DONE. При лимитах/недоступности средств контроля сохранить UNCONFIRMED, не создавать цикл повторов и не покупать ресурсы.

Отчёт: модуль | принято по evidence | в работе | blocker/риск | следующий шаг | ответственный. Процент готовности не высчитывать по числу коммитов. По окончании окна 11.10 остановить именно этот временный контроль штатной automation-паузой и оставить итог/остаток; бессрочное продолжение требует нового поручения.
