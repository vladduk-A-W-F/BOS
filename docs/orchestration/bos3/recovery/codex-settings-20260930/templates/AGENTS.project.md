# BoS · переносимые правила проекта

BoS — связанное управление бизнесом: задача → наглядный сценарий → результат → CRM на тех же данных. Украинский интерфейс; отдельная установка на компанию; факты, документы, движения ресурсов, показатели, ответственные, коммуникация и согласованные действия должны быть связаны проверяемо.

Перед работой сверяй действующее поручение владельца, exact Git-кандидат, актуальное состояние и карточку. Один главный интегратор правит каноническое дерево. Независимые задачи допускаются в отдельных копиях с allowlist; автор не принимает собственный diff. Цикл: карточка → диагностика → правка → независимая проверка → evidence → последовательная интеграция.

Сохраняй исторические лимиты полных запусков, требования 11 gates и отдельные решения о готовности. Синтетические проверки не используют реальные клиентские данные. PostgreSQL-выводы требуют фактического PostgreSQL 16. Не объявляй готовность из конфигурации, draft PR, HTTP 200 или частичного CI. Состояния `TECHNICAL_READY=false` и `PILOT_ALLOWED=false` меняются только по доказательствам и отдельному решению.

В продукте изменения проходят существующий command/service путь, preview и подтверждение; модель не получает произвольный SQL или обход прав. Не расширяй архитектуру или внешние расходы по одному лишь шаблону. Пиши отчёт с source SHA, проверками, exit codes, пропусками, независимым verdict и следующим разрешённым шагом.
