# Переносимый набор настроек Codex/BoS · 30.09.2026

Этот каталог предназначен для **просмотра перед возможным сохранением в GitHub**. Он не является резервной копией приложения или подтверждением восстановления. Ничего отсюда не было установлено в рабочие каталоги, отправлено в GitHub или применено к BoS.

## Что входит

- `templates/AGENTS.global.md` — общие рабочие предпочтения, очищенные от локальных путей.
- `templates/AGENTS.project.md` — компактные правила BoS без исторических разрешений на запуск.
- `templates/config.project.toml` и `templates/agents/*.toml` — роли и инструкции для нового проектного каталога `.codex/`.
- `templates/model-routing.json` — профиль выбора модели; наличие имени модели в файле не подтверждает её доступность после переустановки.
- `STATE_RU.md` — источник, pins и разделение переносимого текста от действующего состояния.
- `PROVENANCE.json`, `SHA256SUMS.json`, `validate_bundle.py` — происхождение и локальная проверка.

**Не входит:** `auth.json`, ключи и токены, переменные окружения с секретами, cookies, браузерный профиль, `rules/default.rules`, логи, SQLite/WAL, сессии, переписки, история чатов, дампы БД, media, automation state и реальные данные. Локальные правила разрешений исключены целиком, поскольку в них обнаружены строки авторизации. Аккаунтные подключения, плагины и доступные модели потребуется проверить после нового входа.

## Как восстановить после переустановки

1. Сохранить отдельно локальную **холодную** резервную копию истории и состояния Codex, если они нужны: закрыть приложение, согласовать состав и место копии, затем использовать штатный способ или отдельную проверенную процедуру. Этот каталог её не содержит. Нельзя загружать полные переписки в GitHub ради восстановления настроек.
2. Склонировать этот каталог в **новую временную папку**, не в живой `CODEX_HOME` и не в канонический репозиторий. Запустить `python validate_bundle.py` из этой папки с Python 3.11 или новее (`tomllib`). Скрипт только читает файлы набора.
3. Открыть все экспортированные тексты и `PROVENANCE.json`, проверить их вручную на частные данные. Автоматический поиск не доказывает отсутствия секретов. Для публичного GitHub нужен отдельный осознанный просмотр.
4. Заменить в шаблонах `<PROJECT_ROOT>` и `<CONTROL_HOME>` на проверенные пути новой машины. `STATE_RU.md` содержит переносимые обозначения путей и датированный срез состояния, который нужно сверить заново.
5. Сравнить шаблоны с новой установкой и текущей версией Codex. Подготовить diff: `AGENTS.global.md` → новый глобальный `AGENTS.md`, `AGENTS.project.md` → проектный `AGENTS.md`, `config.project.toml` → проектный `.codex/config.toml`, `agents/*.toml` → `.codex/agents/`. Не перезаписывать существующие файлы до просмотра diff и решения владельца. Модель, режим доступа и инструменты выбираются действующими инструкциями и реальной средой.
6. Войти в аккаунт вручную; заново подключить нужные сервисы через интерфейс. Для BoS отдельно сверить точный Git HEAD, незакоммиченные изменения, control home, runtime и текущие разрешения. Шаблоны не переводят продукт в READY и не возобновляют прежние задачи.

`SHA256SUMS.json` защищает от случайного изменения файлов внутри набора, но не подтверждает происхождение GitHub-репозитория. Перед загрузкой перепроверить состав и историю будущего репозитория; не добавлять туда локальные состояния и переписки.
