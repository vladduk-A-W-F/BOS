## Проблема й реалізація

Старий `InitialImportFixture.setUp` у `erp/test_initial_import.py` приймав лише basename з префіксом `check_` і відхиляв належну Django test DB PostgreSQL. Відмову фактично відтворено на PostgreSQL 16.15 у `postgres-red-p10-003`: один метод, exit 1, старий `name.startswith('check_')` assertion.

Зміни картки обмежені `erp/test_initial_import.py` і `erp/test_initial_import_isolation.py`. Guard перевіряє environment і завантажений verification profile, backend, видане ім’я source DB, точне ім’я Django test DB та фактичну БД активного з’єднання. SQLite додатково відхиляє файлові aliases source через resolve/samefile. Перевірка передує записам fixture. `scripts/check_support.py`, міграції та runtime-сервіси цією карткою не змінювалися.
