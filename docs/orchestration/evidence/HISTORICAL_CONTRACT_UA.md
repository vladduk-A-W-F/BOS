# BoS · спільний контракт

**Режим виконання від 16.09.2026:** користувач доручив після кожного пункту зупинятися та звітувати. За один хід виконується одна картка; її дозволені підзадачі й незалежний review можна делегувати. Наступну картку без нового повідомлення користувача не починати. Це уточнення має пріоритет над старим безперервним режимом.


Ти виконуєш одну визначену задачу проєкту BoS. Працюй українською. Спочатку прочитай актуальні docs/PROGRESS_UA.md, docs/READINESS_UA.md, master v2.1 і чинні інструкції робочого каталогу. Цей пакет продовжує прийнятий план; він не скасовує його.

Збережи Django й оригінальний frontend, назву BoS з однією S, окрему установку на компанію та заморожений інвентар 85 шляхів / 12 місць. Не переробляй завершене. Історичні БД незмінні; тести — тільки на власних синтетичних БД/media. Не передавай реальні дані зовнішнім процесам. Не додавай новий стек, shared-DB SaaS, черги, платну/локальну LLM або банківський API.

Головний агент — єдиний редактор канонічного дерева. Субагент читає виділений контекст і повертає finding, diff/patch чи логи у своїй тимчасовій теці; у спільному дереві не пише і не комітить. Інший ШІ або зовнішній розробник має ті самі обмеження й отримує тільки дозволені дані. Автор правки не приймає власну роботу як незалежний reviewer.

Не запускай задачу без її передумов. Відрізняй DONE документа/локальне завершення від TECHNICAL_READY і дозволу на пілот. Для коду: справжній red → мінімальна правка → потрібний full → evidence → review → один коміт на атомарну задачу, без amend. Для read-only/документа не вигадуй падаючий тест і не запускай повний набір без зміни перевіреного коду. Нові регресії виправляй до наступної кодової задачі; вже відомі зовнішні блокери зберігають червоний overall.

Усі 11 критеріїв verify незмінні. НЕ ЗАПУЩЕНО і НЕ РЕАЛІЗОВАНО не є PASS. Результат прив’язуй до точних commit/source SHA, середовища, команди й raw output. Старий результат після зміни коду не переноситься автоматично.

Історичні обмеження обов’язкові для КОЖНОГО виконавця:
• A09: ліміт спроб вичерпаний. Жодних нових targeted 13MiB експериментів, у тому числі через CI/новий ID/нового агента. Лише незмінний oracle у необхідному full. Proxy log 413 не заміняє відповідь клієнту.
• A10: activation/upgrade/rollback відхилено автоматичною перевіркою cybersecurity risk. Не повторювати, не перефразовувати і не передавати ту саму дію іншому агенту/інструменту/людині для обходу. Підготовка досьє не дозволяє відхилену операцію. Backup/restore не закриває gate9.
• A11: не повторювати заблоковані CDN/loopback маршрути, не тунелювати. Новий CI — лише справді дозволений стенд. Node/source review не є браузерним прийманням.

Максимум три повні спроби на одну проблему З УРАХУВАННЯМ історії; нове найменування ліміт не скидає. За блокера збережи точну причину й наступну дозволену дію. Не обходь доступи/відмови. Запит до людини потрібен за стоп-умов master: реальні гроші/історія, нові витрати/публікація/реальні дані без дозволу, конфлікт архітектури, зміна критеріїв, новий дефект поза обсягом, який спростовує вже виправлене. Чинне погодження повторно не запитуй; спочатку доведи підготовку конкретного результату до межі рішення.

Наприкінці поверни: ID; що зроблено; що не зроблено; changed files; commit/source SHA; команди/exit codes/raw evidence; findings; статус LOCAL_PASS/DONE/BLOCKED/FAIL; межі висновку; наступну дозволену задачу. Оновити канонічний PROGRESS може лише головний агент. Не оголошуй весь продукт готовим за результатом однієї картки.
