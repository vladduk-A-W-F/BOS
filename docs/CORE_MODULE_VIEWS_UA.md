# Чотири види спільного операційного реєстру

Робочий екран «ERP → Мережа та операції → Операції» використовує серверний реєстр `GET /api/erp/modules/` і той самий Policy-відфільтрований payload `GET /api/erp/network/`. Нова проєкція не створює браузерний облік і не переносить рушій симулятора в робочу базу.

Блоки «Огляд», «Операції», «Документи й звірки», «Контроль строків» збережені. У блоці операцій вибрані філія, точка, валюта, модель і пошук спільні для чотирьох видів. Зміна виду не перезавантажує або не змінює бізнес-записи. Пошук і вибраний вид зберігаються під час оновлення мережевого payload у межах відкритого робочого екрана.

| Вид | Реалізація |
|---|---|
| Контроль | `ERPTable`, колонки з серверного опису моделі, 20 записів на сторінку, відкриття чинної картки |
| Потік | Групування за фактичним `status_field`: станом якості, ефективним станом закупівлі або збереженим статусом; записи без такого поля мають одну колонку без вигаданих етапів |
| Мережа | Чинна карта України та наявні координати пов’язаних точок; для переміщення показані джерело й призначення |
| Фокус | Детермінована черга за минулим строком відкритої роботи, станом якості, браком документів, рухом, утриманнями та доступною оплатою; деталі розкриваються у рядку |

Карта показує точки, а не вигадані координати кожного рахунку чи замовлення. Записи без доступної прив’язки залишаються у реєстрі. Пошук фільтрує лише поля, описані у видимих колонках. Для моделі без ознак уваги «Фокус» пояснює порожній результат і залишає можливість відкрити всі записи у «Контролі».

Вибір точки іншої філії на карті переміщення узгоджує обидва фільтри з фактичним `Location.branch_id`. Вибрана модель, вид і пошук зберігаються. Для переміщень серверний відбір як і раніше визначається точкою відправлення; вибір точки призначення не перетворює вхідний рух на вихідний.

## Дії та права

Реєстр модулів є конфігурацією інтерфейсу. Він не надає прав і не виконує команди. Кнопки відкривають чинні `BoSActionDialog` / `ERPActionDialog` через `onAction`; маршрут preview → confirm, mutex, журнал, перевірка прав і повторне підтвердження лишаються чинними. Перетягування картки не змінює статус.

Записи з підтриманими типами відкривають `BoSInspector`. Для переміщень і утримань є вбудовані деталі, фактичні поля й переходи до прийнятої партії або рахунку. Закриття деталей клавішею Escape повертає фокус до елемента відкриття, якщо він ще присутній.

Поточні права облікового запису та capabilities мережевого payload перевіряються додатково до каталогу. Спостерігач не отримує кнопок змін. Для ролей без фінансів зберігається доступна метаінформація рахунку, але приховуються суми, фінансові причини у «Фокусі», фінансові дії та модель утримань. При помилці HTTP або невідомій схемі каталогу операційні види не підмінюються вигаданим локальним каталогом: показані помилка й повторне завантаження.

Дії opening, invoice, payment, hold_payment, release_payment додатково потребують фінансового capability у поточному обліковому записі, payload та каталозі. Це не покладається лише на загальне `bosCanAction`: наприклад, чинна загальна політика дозволяє менеджеру відкривати invoice, але фінансовий інтерфейс цього реєстру його не показує. Node-перевірка використовує саму функцію `bosCanAction` із поточного frontend, а не її спрощену копію.

Грошові значення у нових видах форматуються як десяткові рядки без `Number`/`float`, без складання різних валют та без перерахунку сум. Ознака додатної суми перевіряється за точною десятковою формою. Порівняння строків використовує серверну бізнес-дату `as_of`.

CSV відкриває чинний серверний експорт з тією самою моделлю, філією, точкою та валютою. За введеного локального пошуку експортне посилання приховане з поясненням: чинний серверний експорт не підтримує такий текстовий фільтр. Кнопка не видає ширший файл за результат локального пошуку.

## Адаптивність і перевірка

Кнопки виду мають `aria-pressed`, пошук і модель — явні підписи; списки уваги використовують нативні `details/summary`. На вузькому екрані панель перемикачів має дві колонки, канбан і картки мережі — одну. Конкретний дефект переносу цифр/«грн» у KPI виправлено: сума лишається одним рядком, розмір шрифту залежить від ширини картки, сітка зменшує кількість колонок. Суми не обрізаються через ellipsis.

`node scripts/checks/module_views.cjs` — нова адресна Node-перевірка компонентів, правил відбору, переходів, експорту, точного форматування та відмови каталогу. JSON-фікстури створені з фактичного `module_registry.build` для синтетичних role/capability-об’єктів; це метадані, не доказ живої авторизації. HTTP-авторизація перевіряється окремими тестами серверного реєстру.

Цей результат не є browser/E2E або WCAG-сертифікацією. Історичні browser CI, повні набори та вичерпані перевірки не повторювалися. Перевірка CSS підтверджує правило розміщення, але не замінює фактичний рендер на пристрої. Нові види не означають готовність AI/OCR-конвеєра, конструктора довільних моделей, Studio, автопроведення чи production activation.
