# BoS · початкове перенесення даних

Початковий імпорт допомагає почати облік у BoS із довідників та невиконаних зобов’язань. Керівник завантажує пакет, перевіряє відповідності й контрольні суми, потім погоджує запис. Перед погодженням нові складські залишки та замовлення не створюються.

## Що можна перенести

| Дані | Що з’явиться у BoS |
|---|---|
| Контрагенти | Покупці та постачальники |
| Номенклатура | Код, назва, одиниця, версія, валюта, вимоги до документів |
| Місця зберігання | Склади для початкових партій |
| Початкові залишки | Партії та їхні початкові рухи; якість очікує перевірки |
| Відкриті продажі | Замовлення, відповідальний та ще не відвантажені позиції |
| Незавершені закупівлі | Лише кількість і витрати, що залишилися до виконання на дату зрізу |

Початковий імпорт доступний керівнику. Документи спочатку завантажуються звичайним приватним маршрутом; пакет посилається на їхні точні код, версію, ID та контрольну суму. Імпорт не завантажує вкладення і не створює історичні оплати, старі приймання або відвантаження.

## Перший навчальний запуск

1. У розділі ERP натисніть **«Початковий імпорт»**.
2. Оберіть відповідального за навчальні замовлення й формат JSON. Завантажте згенерований приклад. Він має власні коди, тому не підміняє ваші записи.
3. Завантажте цей JSON у поле пакета й натисніть **«Перевірити пакет»**. Перегляньте помилки, попередження, кількість нових записів і таблицю відповідностей.
4. Звірте контрольні суми джерела з вашим файлом. Окремо перегляньте, що буде додано, і стан записів пакета «Було → Стане».
5. Погодьте імпорт. Збережіть квитанцію та відкрийте створені картки. Для залишків перейдіть до партії й виконайте реальну перевірку якості перед використанням.
6. Повторно перевірте той самий пакет. BoS покаже попередній результат та вже перенесені записи; повторне погодження не має додавати залишок удруге.

Навчальний приклад містить окремі EUR, USD та UAH. Він не підходить для завантаження реальних початкових залишків без їхньої звірки.

## Підготовка власного пакета

Оберіть одну дату зрізу: це межа між старою системою та новими операціями у BoS. Використовуйте стабільний простір зовнішніх кодів `namespace` для одного джерела. Кожний рядок має сталий `external_id`; назва запису не є його ідентифікатором.

- JSON: один файл у форматі згенерованого прикладу.
- CSV: окремий manifest та таблиці, перелічені в ньому. Завантажте кожну таблицю у відповідне поле форми. Службова відповідь із переліком файлів не є manifest.
- Один пакет: до 100 рядків разом із прив’язками, до 128 KiB вмісту. Для великих обсягів підготуйте узгоджені пакети з тим самим простором кодів і явними посиланнями.
- Кількості передавайте десятковими рядками до трьох десяткових знаків, ціни й витрати — до двох. Наприклад, `"1.250"` та `"2.34"`. Кома й експоненційний запис не підтримуються.
- Суми зберігаються окремо за EUR, USD, UAH, без ПДВ та автоматичного перерахунку валют.
- Дати мають формат `YYYY-MM-DD`. Історичний строк закупівлі може бути простроченим: це факт джерела, який BoS зберігає.
- Помилка будь-якого рядка зупиняє весь пакет. Виправте джерело і перевірте його повторно; часткове мовчазне перенесення не виконується.

Поле `expected_source_control_totals` містить контрольні кількості й суми, підготовлені з вихідного обліку. Це окрема перевірка повноти: не змінюйте його тільки для того, щоб приховати незрозумілу різницю з попереднім переглядом.

## Якщо запис уже існує

У формі розкрийте **«Явно пов’язати з наявними записами»**. Вкажіть тип, точний зовнішній код і оберіть потрібний запис BoS за назвою та кодом. Підтримуються контрагенти, номенклатура й місця зберігання. BoS не зіставляє їх за схожістю назви.

Прив’язки з форми додаються до прив’язок файлу. Якщо один зовнішній код вказано двічі, виправте пакет: форма не перезаписує його непомітно. Повтор раніше перенесеного незміненого рядка використовує попередню відповідність. Змінений рядок із тим самим зовнішнім ID є конфліктом; для виправлення проведеної операції потрібний окремий процес коригування.

## Як читати перенесену закупівлю

Приклад EUR: старе замовлення на **8 шт.**, до зрізу отримано **3 шт.**, залишається **5 шт.** за ціною **1,23 EUR**. Із початкових додаткових витрат **0,80 EUR** на залишок припадає **0,40 EUR**.

У BoS створюється замовлення на 5 шт. вартістю **6,55 EUR**, із нульовим новим прийманням. Після фактичного приймання 2 шт. залишається 3 шт. вартістю **3,93 EUR**. Дані про старі 8 і 3 шт. залишаються у збереженому джерелі; нові складські рухи на старі 3 шт. не вигадуються.

Початкові складські партії задаються окремо. Не переносіть отриману раніше кількість двічі — одночасно як нове приймання та початковий залишок.

## Квитанція, повтор і збій зв’язку

Квитанція першого виконання містить відповідності записів, контрольні суми, фактичне додавання і стан на момент імпорту. Вона не переписується після подальших приймань або продажів. Поточний стан показують картки BoS; контрольна сума джерела не є сьогоднішнім залишком.

Якщо погодження завершилося без отриманої відповіді, скористайтеся **«Повторити погодження»** або **«Перевірити результат»**. Не створюйте інший зовнішній код для тієї самої операції. Ідентифікатори незавершених запитів зберігаються в поточній вкладці, доки не отримано квитанцію; перед закриттям вкладки збережіть файл пакета й зафіксуйте введені у формі прив’язки, яких немає у файлі. Після нового входу той самий пакет із тими самими прив’язками можна перевірити заново.

Погодження обмежене строком і станом даних. Якщо воно застаріло, перевірте той самий пакет повторно. Сервер перевіряє попереднє виконання за ідентифікаторами пакета та рядків.

## Межі цієї версії

Це початкове перенесення для ізольованої компанії. Воно не замінює бухгалтерське закриття, звірку реальних даних або фінансове коригування історії. Браузерне приймання і загальний статус MVP визначаються окремими фактичними перевірками; актуальні докази містяться в `evidence/B02/` та `docs/PROGRESS_UA.md`.
