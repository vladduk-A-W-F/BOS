# Локальный просмотр BoS

Это support-код для отдельного экземпляра продукта с явно синтетическими данными UAH и EUR. Он не подтверждает готовность production или pilot. В checkout хранится только support-код. Runtime по умолчанию: `D:/3/Codex/2026-09-20/bos-execution/work/continuation-review-demo-20260920`, отдельный соседний каталог вне checkout. Внутри runtime код фиксируется в `source`, данные — в `data/review.sqlite3`, документы — в `media`; там же находятся private/logs/evidence/process.json/control/temp. Подготовка отклоняет вложенность runtime/source в любом направлении. Старый review-demo не переносится и не изменяется.

Планируемый адрес: `http://127.0.0.1:8876/`. Он считается проверенным только после появления runtime `evidence/http-readiness.json` и `evidence/browser-review.json`. До этого скрипты являются подготовкой запуска. Readiness проверяет публичный `/api/auth/csrf/` с `mode=working`, `authenticated=false`, HTML и SHA приложения; защищённый runtime endpoint анонимно не вызывается. Проверки не дают acceptance PASS.

В PowerShell из этой папки:

```powershell
.\start.ps1
.\show-login.ps1
# Откройте http://127.0.0.1:8876/ и введите показанные логин и пароль.
.\stop.ps1
```

`show-login.ps1` показывает пароль только в вашем терминале. Не копируйте его в чат, Git или отчёты. Файл `private/user-secrets.dpapi` зашифрован Windows DPAPI для текущего пользователя; пароль не хранится в коде или текстовом файле. После обычного входа выберите «Виробництво», затем «Розпочати роботу» и «Сьогодні», если новый профиль показывает вводный экран.

Владелец создан штатной командой `bootstrap_bos_owner` на пустой базе, роль CEO, без `staff`/`superuser`. Для просмотра документов явно выданы права `view_document` и `download_document`. Синтетические данные добавляются штатными seed-командами при первоначальной подготовке. Запущенное приложение работает в режиме `working`, поэтому кнопка учебного входа и API обхода входа недоступны. Платные AI API не подключены.

Start/stop/status/prepare используют один Windows named mutex; второй одновременный вызов отклоняется. До создания процесса атомарно сохраняются pending intent и nonce. Child до импорта Django сообщает собственные PID/время создания/exe и identity launcher, затем ждёт подтверждения от родителя, который держит проверенные process handles. Неизвестная или несовпавшая identity никогда не разрешает остановку по одному PID. При ошибке или Ctrl+C выполняется cleanup только доказанной пары либо сохраняется `process.json` для `stop`; если handshake ещё не получен, child не импортирует приложение и самостоятельно выходит после таймаута gate. Pending record не удаляется при недоказанном владении.

Остановка сверяет PID, время создания и exe для child и launcher через удерживаемые handles, проверяет завершение обоих и сохраняет `control/<nonce>/stopped.json`. Успешный start оставляет сервер работающим после выхода контроллера; JobKillOnClose не применяется. База, документы и учётная запись сохраняются; повторный старт не делает seed и не стирает изменения. Если порт занят или код отличается от принятого снимка, запуск прекращается с диагностикой. При pending/неизвестной identity повторный start запрещён до разрешения владения; повторный `stop` может использовать поздно появившийся handshake. Автоматического удаления runtime здесь нет.

Первоначальную подготовку выполняет ответственный за интеграцию, указывая точный принятый `--source` и `--expected-source-sha`. Manifest находится в runtime `prepared.json`; он фиксирует SHA продукта и отдельные SHA support-файлов. Изменение support после подготовки также запрещает start. Обёртки используют существующий `vertical-ua/venv/Scripts/python.exe`, не копируют runtime Python. `-RuntimeRoot <absolute-path>` в PowerShell или `--runtime-root <absolute-path>` в Python позволяют явно выбрать другой runtime вне source. Browser check принимает тот же параметр. Секреты нельзя передавать в аргументах команд; show-login используется только в пользовательском терминале. Unit tests и stdlib child proof проверяют управление процессом без BoS/browser/DB и не заменяют независимый review или запуск стенда.
