# Звіт перевірок · 10.09.2026

Статус: локальна збірка для перевірки й демонстрації. Повне приймання на Windows та в браузері ще не пройдене. Готовність до комерційного серверного запуску не заявляється.

## Функціональні перевірки

49 інтеграційних ERP-перевірок пройдено. Наскрізний сценарій охоплює потребу, конкуруючий резерв, приймання, перевірку документів, передачу підряднику, резерв матеріалів, послідовність операцій, списання, випуск, якість, часткове відвантаження, рахунок, оплату, повернення та звірку кожного залишку з журналом рухів. Перевірено повтор погодження, застарілі дані, ролі, зміну версії, надлишкове приймання, переплату, різні валюти, дробову точність матеріалів, пізніше виявлений дефект та відповіді асистента з поточної бази. Деталі — `TEST_ERP.json`.

Додатково 22 незалежні перевірки робочого простору: повний SO-101 за 21 погоджену операцію, узгодженість показників після кожного кроку, документи, місця приймання, валюти, повтори й конфлікти. Деталі — `TEST_WORKSPACE.json`.

Загалом: 151 функціональна перевірка (22 робочого простору + 49 ERP + 48 операційних + 32 оригіналу) та 5 перевірок логіки запуску. Усі пройдено. Ці числа не включають окрему оцінку 26 сценаріїв нижче.

48 інтеграційних перевірок нової підсистеми пройдено на тимчасовій базі в пам’яті. Перевірено контрольні значення dataset; R01 для 5 і 25 одиниць; R02 без придатної пропозиції; R03 з простроченою пропозицією; реальне створення й зміну статусу Task; журнал; повтор без дубля; чуже погодження; спостерігача через нові й старі маршрути; CSRF; строк погодження; конфлікт зміни заявки, доручення й документа; пошук актуальної версії; завантаження джерела; DOCX/XLSX/PDF; порожній скан; пошкоджений і завеликий файл; ручну перевірку документа; власну заявку й пропозицію; неприпустимі інструменти; відсутність зовнішньої відправки; відсутність підміни валют.

32 регресійні перевірки оригіналу пройдено: доступність основних маршрутів, створення співробітника й доручення, зміна статусу, пошук, помилки, локальні бібліотеки, наявність первинних розділів та контраст базових пар.

5 перевірок логіки запуску пройдено із заміною встановлення на тестові виклики: повтор після незавершеної установки, перевірка контрольної суми залежностей і діапазон Python. Це не фактичний запуск Windows і не нове мережеве встановлення всіх пакетів.

Збірка JSX, синтаксис JavaScript та перевірка невизначених посилань компонентів пройдені. Це не замінює браузерну перевірку.

Оригінальну базу окремо скопійовано в тимчасовий файл і застосовано міграції: 15 співробітників, 48 підрозділів і 0 доручень залишились без змін. Імпорт demo у робочому режимі заблокований. Контрольна сума оригінального файла до й після збігається; див. `ORIGINAL_INTEGRITY.json`.

## 26 сценаріїв

Фактичні відповіді й операції збережено в `EVALUATION_RESULTS_UA.json`: 20 локальних сценаріїв пройдено; 2 серверні операції пройдено; 3 часткові; 1 перевірений лише локально. Часткові: вільний текст доручення потребує форми, невідоме ім’я потребує ручного вибору, погоджувана зміна терміну доручення ще не реалізована (перенесення строків ERP-закупівлі та виробничої роботи вже працює). Запит іншої компанії відхиляється, але це не доказ серверної багатоклієнтської ізоляції.

Зовнішню модель не викликали. Якість її відповідей, витрати, тайм-аути та стійкість до ін’єкцій не тестували.

## Візуальний напрям

Графітова база, системний шрифт, постійні підписи навігації, нативні поля й діалоги, видимий фокус, окрема прокрутка таблиць, відключення декоративних рухів. Для нових головних кнопок задано мінімальну висоту 42 px. Вихідна палітра є дизайнерським рішенням, а не універсальним стандартом.

Контраст перевірених пар: основний текст 16,07:1; вторинний 6,12:1; підписи 7,34:1; текст на основному акценті 10,85:1; повідомлення помилки 9,17:1. Ці результати не охоплюють усі графіки, прозорі шари й альтернативні теми.

Первинні орієнтири W3C:

- https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html — мінімальний контраст тексту.
- https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html — мінімальні розміри цілей і винятки.
- https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html — інформація не лише кольором.
- https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html — видимий фокус.

Браузерний перегляд не запустився через несумісність середовища перегляду з цим Django-проєктом. Не перевірено: фактичний вигляд на 390/768/1440 px, масштаб 200%, послідовність фокуса, Escape і мобільне введення. Повну відповідність WCAG не заявлено.

## Середовище й відтворення

Python 3.12.14, Django 6.0.5. PDF-парсер перевірено на локально наявному pypdf 6.10.0; та сама версія зазначена в requirements. Нове завантаження пакетів тут не виконано. У встановленому середовищі проєкту:

```text
python scripts/check_workspace.py
python scripts/check_erp.py
python scripts/check_operations.py
python scripts/check_original.py
python scripts/check_launcher.py
python scripts/evaluate_scenarios.py
node scripts/build_frontend.cjs
node scripts/check_frontend.cjs
```

Перевірки працюють на окремих даних і не запускають сервер. JSON-звіти містять назви перевірок, фактичні результати й неперевірені області.


Незалежне приймання та виправлення за зауваженнями: `MVP_REVIEW_UA.md`. Старі відокремлені демонстраційні KPI прибрано з головних екранів; нові суми звіряються з ERP. Графіки прогресу відображають виконання позицій і оплату конкретних рахунків.
