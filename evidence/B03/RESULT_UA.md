# B03 · повернення, скасування та коригування · локальний результат

12.09.2026, версія **0.2.13-dev**. Код інтегровано після незалежного огляду й повного verify №23 на Linux / Python3.12.14 / SQLite3.53.1. Нових локальних регресій немає. Це контрольна точка розробки, не приймання всього MVP.

## Поведінка

Шість дій пов’язують скасування невиконаного залишку, повернення конкретного приймання/відвантаження, кредитове коригування рахунку, повне сторно кредиту та окреме погодження вимоги постачальнику. Кожна дія має джерело, причину, дату, попередній перегляд впливу й погодження. Первісні кількості, поставки, рахунки, оплати та події не переписуються. Складська оцінка повернення виділяється з фактичної вартості його джерела до копійки; вона не визначає погоджену компенсацію.

Рахунок показує первісну суму, чинний кредит, фактичні оплати, залишок до оплати й кредит клієнта окремо. EUR/USD/UAH не складаються. Квитанція зберігає перший результат, поточна картка відображає наступні зміни. Новий read-only пошук результату за action/operation_id перевіряє поточну роль та історичні джерела; unknown не означає, що запису немає. Повтор того самого наміру не створює нових рухів.

Нові форми доступні з карток ERP, закупівлі та JSON асистента. Імпортований UUID зберігається після редагування, скасування PO має власний підсумок. Старі ERP форми та B02 імпорт збережені. Інструкція — `docs/CORRECTIONS_UA.md`.

## Докази до та після

Початкові чотири actual HTTP сценарії відмовили через unknown action; після реалізації ті самі4/4 пройшли. Незалежний огляд додатково відтворив і виправив видимість історичних документів, показ існуючої партії в preview, вплив зовнішнього Decimal context, скасовані поставки в ETA, дубль проєкції Event та витік фінансового стану через підказку менеджера. Фактичні SQL-відмова й retry довели повний відкат без часткового складського ефекту. Три валюти, дробова вартість0/.01/0, комерційний і фізичний бюджети кредиту, імпортовані поточні кількості та міжопераційна конкуренція мають окремі регресії.

Source/JS огляд UI відтворив відмову шести JSON дій, втрату imported UUID при редагуванні та неправильну пораду приймання після повного скасування. Після правок exact Babel відповідає джерелу; named source checks пройшли. Ці вузькі перевірки не є браузерним або HTTP UI прийманням.
