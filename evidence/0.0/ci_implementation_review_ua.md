# BoS · перевірка реалізації 0.0

11.09.2026. Переглянуто `verify.py`, `check_support.py`, `verification_settings.py`, GitLab CI, Compose та обидві обгортки. Checkout не змінено. Це обмежений огляд каркаса, не приймання продукту.

1. **Виправити: SHA доказу Windows не покриває весь виконуваний комплект.** `source_digest()` пропускає `assets/app.js`, `manage.py`, `scripts/*.sh`, `scripts/*.ps1`, `START*.bat` і текстові fixtures `operations/seed/documents/*.md`. На тимчасовому дереві незалежно відтворено: зміна `assets/app.js`, `verify.ps1` або `manage.py` не змінює SHA; зміна контрольного `.py` у `scripts` змінює. Додати всі runtime/assets/launcher/fixture файли до визначеного manifest; зберегти нормалізацію CRLF для порівняння ОС.
2. **Виправити: Windows venv потрапляє до копії тестового проєкту.** `tests-windows` створює `.venv-ci`, але `copytree(ignore=...)` виключає лише `.venv` і `venv`. Перевірка чинного ignore повернула `False` для `.venv-ci`. Це зайве копіювання встановленого середовища та ризик переповнення довжини шляхів у Windows. Виключити `.venv-ci`; краще явно копіювати потрібні корені й файли та синтетичні fixtures, щоб майбутній локальний backup у новому каталозі також не потрапляв у копію.
3. **Підтверджено читанням: небезпечного DROP робочої БД не знайшов.** Ім'я випадкове `bos_verify_<hex>`, `created=True` ставиться лише після успішного CREATE, DROP використовує `sql.Identifier` і виконується тільки для цієї створеної БД. Немає fallback PostgreSQL → SQLite. Реального PostgreSQL у цьому огляді не запускали.
4. **Підтверджено читанням: поточний full не може стати green за відсутніх gates.** Нереалізовані файли дають `НЕ РЕАЛІЗОВАНО`, відсутнє середовище `НЕ ЗАПУЩЕНО`, дочірня помилка `ПОМИЛКА`; `complete` вимагає всі gates. Assertion optimization заблоковано, legacy counts та фактичний vendor перевіряються. Майбутні extension scripts мають самі доводити всі підкритерії: зараз їхній контракт — тільки exit code, тому діагностичні scripts з exit 0 сюди включати не можна.
5. **Підтверджено читанням: Windows не optional.** `allow_failure: false`, звичайний `needs`, перевірка Windows/Python 3.12, gates 1/2/3/6, SHA і поточного pipeline. Без цього job повний конвеєр не може бути прийнятий. Пункт 1 вище необхідний, щоб перевірка SHA була змістовною для всіх виконуваних файлів.
6. **YAML синтаксично коректний.** `yaml.safe_load` успішно прочитав `.gitlab-ci.yml` та `docker-compose.yml`; структура потрібних jobs, service `postgres:16` і loopback port присутні. GitLab CI Lint та реальний runner не запускалися: PyYAML не підтверджує прийняття конфігурації сервером GitLab. Windows job потребує доступного Docker з Linux containers та користувача ранера з правом запуску Docker; це має бути передумовою інструкції.
7. **Дані: бази не відстежуються Git, але копіювання не є allowlist.** У `git ls-files` немає `db.sqlite3`/`BoS_Demo.sqlite3`; ignore прибирає їх із temporary source, замість них створюється синтетичний sentinel. Робочі БД не мігруються. Водночас `shutil.copytree(ROOT, ...)` підхопить довільні невиключені локальні каталоги; виправлення з пункту 2 усуне цей клас ризику. Наявний висновок не є аудитом кожного документа на персональні дані.
8. **Підсумок.** Перед завершенням 0.0 виправити два конкретні дефекти каркаса з пунктів 1–2 і перевірити їх локально. Інших підтверджених блокувальних дефектів у розглянутих файлах не знайшов. Зовнішнє приємання 0.0 залишається незапущеним до реального CI URL/виводу; незапущений прогін не підміняється статичним оглядом.
