Окремий owned workdir із випадковим ім’ям; DB `check_<32hex>.sqlite3` та MEDIA зовні checkout, видані існуючим guard до з’єднання. Не читати і не копіювати `db.sqlite3` чи `BoS_Demo.sqlite3`. Не змінювати оригінальні demo-команди для зручності тесту. Зупинка — лише процесів із власних Popen handles. Trace/відео містять лише синтетичних користувачів; паролі і cookies не друкуються в звіт.

Скористатися готовим `fixtures/synthetic/transfer.py` для погоджених команд і точних типів, але не викликати populate на вже заповненій базі. Реальні mutation-сценарії отримують окремі свіжі установки або індивідуальні записи з незалежними початковими фактами; тест не «скидає» історію між кроками.

## 5. Матриця розмірів і клавіатури

Повний обов’язковий набір: ширини **390, 768, 1440 px**, кожна при 100% і **справжньому браузерному zoom 200%**. Базові висоти зафіксувати, наприклад 844/1024/900; записати outerWidth, innerWidth, visualViewport.width/scale, devicePixelRatio, фактичний zoom і screenshot для кожного випадку. Відкритий UI не повинен залежати від попереднього розміру або localStorage іншої ролі.

`deviceScaleFactor: 2`, CSS `zoom:2`, `transform:scale(2)` та CDP pinch scale самі по собі **не є доказом user zoom 200%**. Перед прийманням отримати реальний browser zoom в Chromium (наприклад, підтримувана дія самого браузера у headed CI) і перевірити його незалежно. Якщо headless не змінює zoom клавіатурним скороченням, не ставити PASS: гілка залишається НЕ ЗАПУЩЕНО до реального запуску. Структурний тест еквівалентного вузького viewport може бути лише додатковим.

На кожній комбінації перевіряються: вхід, перший onboarding, BoSHome, продажі, склад, закупівлі, документи, ERP-погодження та вкладений інспектор. Для manager/observer пройти дозволені навігацію й картки на 390 і 1440; повну матрицю видимості форм доповнює окремий UI-ROLE-01. Backend gate4 не замінюється цим скороченим браузерним переліком.

Критерії layout: жодна основна кнопка чи заголовок не обрізані зовнішнім `overflow:hidden`; сторінка доступна вертикальним скролом; таблиця може мати власний горизонтальний скрол, але всі стовпці досяжні клавіатурою; діалог і його дії досяжні при 200%; довге ім’я не накладається на кнопку. Для кожного видимого інтерактивного елемента зняти bounding box та, за потреби, перевірити elementFromPoint у точці натискання. Повний скриншот сам по собі не доводить доступність прихованої кнопки.

Не підміняти продукт fake API, не генерувати успішну відповідь у браузері. Механізм несправності, момент DB-commit та hash реального payload зберегти в evidence. Якщо обрана бібліотека не дає точної точки обриву, цей сценарій незапущений, а не пройдений через інший тест.

## 7. Порядок реалізації без зміни стеку

1. Після фіксації окремого A10 root бере A11. Записати власну поточну SHA/базу доказів. Додати `scripts/check_ui.py` як реальний wrapper, що перевіряє browser prerequisites, створює лише owned synthetic fixture, запускає справжній сервер/браузер, збирає JSON/trace/screenshots і повертає ненульовий код за будь-якого незапущеного обов’язкового випадку. Наявний gate10 уже викликає саме цей шлях; змінювати список gates не потрібно.
2. Перший реальний browser run має зберегти червоні результати для конкретної прогалини. Відсутній executable — лише `НЕ ЗАПУЩЕНО`, не доказ помилки frontend. Спочатку UI-NET-02 та UI-FIN-01, оскільки вони стосуються складу/грошей; потім навігація/фокус/читаємість у межах A11. Не рефакторити старий неактивний Dashboard.
3. Мінімальні зміни тільки джерела JSX/наявних helper; штатний `node scripts/build_frontend.cjs` оновлює 2 згенеровані файли. Повторити той самий browser oracle. Не послаблювати test через `.first()`, довільний sleep, видалення кнопки, вимкнення фінансового розділу або пропуск помилки console.
4. `BOS_PYTHON=<перевірений Python> bash scripts/verify.sh --suite ui --output evidence/A11/ui/report.json` — реальний gate10. Після локального виправлення — повний `--suite full`, який збереже червоний стан інших непройдених gates. Не зараховувати A09 13 MiB як пройдений і не робити нових спроб його виправлення в A11.
5. Окремий Windows job із Python 3.12 за master. Gate11 — Windows критерії 1–3 і 6; browser gate10 не доводить Windows. Тут Windows відсутній і не запускався. Інструкція self-hosted runner не є результатом запуску.
6. До A11 evidence: commands, stdout/stderr, реальні platform/Python/Django/Playwright/Chromium versions, source SHA, fixture manifest SHA, viewport/zoom proof, кожен case з pass/fail/unrun, HTTP/DB assertions, screenshot і trace path, `complete=false` доки є unrun/fail. Не додавати secrets/storageState до публічного ZIP. Окремий незалежний огляд; лише тоді один A11 commit і оновлення PROGRESS/CHANGELOG.

## 8. Що не є закритим цією роботою

Не виконано жодного browser case, Windows case чи gate10. Не підготовлено реліз. Не реалізовано B01 переходу рекомендації у Purchase, B02 імпорту залишків, B03 фінансових корекцій повернень, C01 повного життєвого циклу доручення чи C03 банківського звіряння: UI-тести мають враховувати поточну чергу, не підміняти ці задачі картками й поясненнями. Наявні невиконані умови PostgreSQL, Windows, зовнішнього CI і A09 залишаються явно відкритими.
