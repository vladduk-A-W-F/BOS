# A08 · відновлення незалежних перевірок після перерви

12.09.2026. Перевірено фактичний локальний код A07 + ранню інтеграцію A08. Тести відновлено з видимого контракту; це новий фактичний red, а не відновлення втрачених журналів на словах.

- 11 HTTP-методів: 10 перевірок upload/quota/rollback/access та додаткова відмова для прив’язаного файла з `size=NULL`.
- 1 метод реального typed export з вкладеним приватним шляхом та фактичною `umask=022`. Перевіряє всі створені каталоги й файл; потім читає експортований файл штатним `PrivateDocumentStorage`.
- Жодного mock виконання бізнес-функцій: Django HTTP client, CSRF, файлові байти, реальні SQLite транзакції та тригер пізньої відмови.
- Одночасні завантаження мають спільну квоту 10 байтів, історичний BLOB 5 байтів і два запити по 5 байтів. Кінцевий критерій `[201,422]`, один новий запис, один приватний файл, 10 сумарних байтів. Після трьох негайних 409 повтор можливий тільки після завершення обох реальних потоків, усередині тієї самої квоти. 409 не приймається як доказ правильної квоти.

## Фактичний red

Журнал: `a08_upload_recovered_before.log`. Із 12 цільових методів 7 впали (10 assertions, 0 errors), 5 пройшли. Перший loader також знайшов 14 імпортованих старих A07 тестів; вони пройшли. Імпорт змінено на alias модуля для уникнення зайвого discovery; умови приймання не змінювались.

Відтворено:

1. `size=NULL`: download 200 замість 422.
2. Паралельні HTTP: `[201,201]` замість `[201,422]`.
3. Квота legacy BLOB + фізичні файли і межа в один байт ігноруються.
4. Некоректні значення квоти -1 / True / '10' / None не блокують запис.
5. Новий upload залишає оригінал у BLOB.
6. Експорт створює `media/documents` з 0755, хоча `media` і `media/documents/ab` мають 0700, а файл 0600.

Бази та файли синтетичні, створені окремо в тимчасових каталогах; оригінальні робочі бази не відкривались і не змінювались. POSIX mode assertion запускається лише на POSIX; фактичні Windows ACL та PostgreSQL не перевірені цим набором.
