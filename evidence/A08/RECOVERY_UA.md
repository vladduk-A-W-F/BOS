# Поновлення після відключення середовища

12.09.2026 робоче середовище відновилося на ранішому знімку A08. Git HEAD `0ffe13e` та прийнята A07 збережені. SHA обох оригінальних SQLite збіглися з попередньою перевіркою.

Не збереглися пізні upload tests, їхній журнал 41/41, остаточна інтеграція upload і A07 FileField descriptor, чернетка document migration та журнали двох зауважень reviewer. Попереднє повідомлення 41/41 описує тодішній запуск, але не підтверджує відновлений знімок. Повний Django запуск до відключення не має отриманого результату.

Відновлено актуальний private_storage з уцілілої чернетки (SHA a75302954c9e01f32c6126b20b47bf32dd71bbd40fdc6ba75ff01b1762eca3f3), 22 файлові тести та наявні первинні журнали. Upload, перенесення й незалежні зауваження перевіряються знову. Це відновлення незавершеної A08; історія Git та заморожені 85 шляхів / 12 місць не переписуються.

Два відкриті зауваження: нові проміжні каталоги експорту мають створюватися приватними; bound-документ без точного size має отримувати відмову. Для них потрібні відновлені реальні red та green журнали.

Перший відновлювальний прогін: 31 метод, одна відмова. Уцілілий старий файловий тест вимагав відмову для спільного MEDIA_ROOT 0755, тоді як прийняте пізніше уточнення дозволяє такий корінь для сумісності зі старим ChatFile. Відновлено точну умову: відмова для приватного підкаталогу `documents` із 0755, без chmod і без нового файла. Окремий ownership-тест перевіряє допустимий MEDIA_ROOT 0755, приватні дочірні каталоги 0700 й незмінність старого файла. Історичний контракт чернетки та первинний лог залишено як історію; поточний контракт — `docs/DOCUMENT_STORAGE_UA.md`.
