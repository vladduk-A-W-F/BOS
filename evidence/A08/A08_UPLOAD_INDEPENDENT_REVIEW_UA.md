# A08 · незалежне приймання upload і приватного експорту

12.09.2026. Висновок: **локальний scope погоджено**. 12 цільових методів пройшли незалежним запуском за 0,667 с, exit 0, без failures/errors. Журнал: `a08_upload_independent_after.log`. Точні SHA переглянутих файлів наведено в `A08_UPLOAD_INDEPENDENT_REVIEW.json`.

## Що перевірено

Новий HTTP upload має чинні рольові та версійні обмеження, спільний ERP mutex, зовнішню durable-транзакцію і квоту до прив’язування файла. Після SQL-відмови cleanup використовує лише видану цьому сховищу незмінену квитанцію нового файла. Успішний commit спочатку фіксує стан committed і відкликає право cleanup; помилка callback не прибирає вже прив’язаний файл.

Фактичний паралельний результат — один 201 та один 422 (другий потік пройшов два проміжні 409). У базі один новий документ, один приватний файл і рівно 10 зайнятих байтів разом з історичним BLOB. Прийняття 409 замість перевірки квоти не застосовується.

Відсутній точний розмір прив’язаного файла тепер відхиляється до видачі чи погодження, навіть коли SHA правильний і є чинний історичний BLOB. Для відсутнього/пошкодженого файла fallback також відсутній. Права доступу перевіряються перед перевіркою вмісту.

Typed export створює кожний новий компонент приватного шляху з 0700. Реальний експорт синтетичної SQLite та bytes перевірив 0700 для `media`, `media/documents`, `media/documents/ab`; файл має 0600 і читається штатним private storage. SHA джерела та повний media manifest залишились незмінними.

## Оцінка відновленого файлового тесту

Зміна старого тесту з відмови для всього `MEDIA_ROOT=0755` на відмову для приватного `documents=0755` правомірна. Це повернення до вже прийнятого контракту сумісності зі старими ChatFile, а не зняття вимоги приватності. Окремий ownership-тест перевіряє дозволений спільний корінь 0755, незмінні історичні байти/0644 і нові приватні дочірні каталоги 0700. Історичний red та пояснення збережені в RECOVERY_UA. Повторно 22 файлові методи тут не запускались: переглянуто їхні умови та root-покриття без дублювання повного набору.

## Межі висновку

Цей review не приймає ще не завершений migration wrapper/rehearsal, повний verify, PostgreSQL чи Windows ACL. Частина 22 історичних файлових перевірок використовує POSIX chmod/mkfifo; адаптація фактичного Windows приймання залишається в A11. Успіх Linux не позначає Windows зеленим. Реліз не прийнято.

Блокувальних зауважень у перевіреному локальному scope не залишилось. Робочі бази, checkout та історія Git reviewer не змінював.
