# C03 · ідентичність джерела при відновленні погодження

Рішення root від 12.09.2026 після незалежного UI review. Це вузьке доповнення до зберігання тільки ідентифікаторів у sessionStorage, без нових API або прав.

При імпорті однакових байтів у тій самій парі джерело/рахунок сервер повертає першу незмінну квитанцію. Її document_id може законно відрізнятися від повторно завантаженого документа. Самого порівняння document_id недостатньо; неперевірений receipt не можна приймати після reload.

До import pending додається тільки source_identity_sha256: SHA-256 UTF-8 JSON масиву [source_sha256, source_system, account_ref], у цьому точному порядку, без trim або зміни регістру. Вхідні значення беруться з перевіреного payload перед першим confirm. Raw source_system/account_ref, суми, призначення, підстави й повний payload не зберігаються у sessionStorage.

Digest обчислюється та записується разом із proposal ID до POST. Crypto/storage error блокує POST. При confirm та відновленні того самого ID UI обчислює digest трійки з receipt і порівнює з очікуваним. Після збігу інший first document_id не є помилкою. Mismatch або відсутній digest не підтверджує виконання: квитанцію не показувати як підтверджену, pending не видаляти, новий намір автоматично не створювати.

Для reconcile зберігаються попередні line_id та allocation keys; цей addendum не додає фінансового payload до storage. Backend domain keys і незмінні квитанції не змінюються.
