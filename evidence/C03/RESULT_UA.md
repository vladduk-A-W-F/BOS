# C03 · виписки, рух грошей та погашення рахунків

Локальний крок 0.2.15-dev пройшов повний інтегрований verify №26 без нових локальних регресій. Це не приймання всього MVP: complete=false, exit1; зовнішні/операційні блокери збережено за незмінними 11 критеріями.

## Що додано

CEO завантажує приватний CSV, перевіряє оригінал і окремо погоджує імпорт. Рядки мають сталі зовнішні ID, джерело й контрольну суму; однакові або частково спільні файли не дублюють уже відомі рядки. Конфлікт даних під тим самим ID відхиляє файл цілком.

Імпорт не створює грошей. Звірка окремо створює одну транзакцію або прив’язує наявну та окремо розносить надходження на клієнтські рахунки. Історична оплата повторно не проводить paid. Bound Transaction зберігає первісні фінансові поля; архівування не скасовує грошовий рух. EUR/USD/UAH рахуються окремо. Картки показують оригінал, першу квитанцію та поточний стан; втрачена відповідь перевіряється тим самим погодженням.

Три additive таблиці зберігаються разом із попередніми 53; історичні ID, поля та receipts не переписуються. Модуль не виконує банківських переказів, FX, AP-рахунків або автоматичного повернення грошей. Наступний D03 уточнює користувацькі інструкції та назви фактичного меню.

## Збережені помилки й незалежний огляд

До інтеграції actual red зафіксували source replay/bound Transaction, status-filter, current-summary/export references, duplicate historical payment в одному намірі, C03 body limits та historical schema dependencies. Мінімальні виправлення пройшли окремі перевірки та незалежні exact-SHA reviews. UI51 extracted-JS checks і189 незмінних declarations є допоміжними доказами, не браузером. Full26 підтвердив остаточну спільну версію; жоден старий oracle/11gate не послаблено.

Історичні typed fixtures тепер вимагають точний набір56, зберігаючи старі53; genuine historical migration targets закріплені без видалення старих assertions. Новий recorder oracle враховує рівно один реальний migration INSERT; усі business high-water незмінні. Повний native restore зберіг усі16 старих критеріїв і2 додаткових. E2E oracle був заморожений до actual run і не змінювався під результат.

Джерела: INTEGRATION_SHA256.json; backend/ui/access/concurrency/restore/e2e; before/after журнали; незалежні reviews; verify-1/report.json та gate-06-actual.json. ## Відкриті умови

PostgreSQL, Windows і зовнішній CI не запускалися. Upgrade/rollback і browser gate не реалізовані/не прийняті в цьому контурі; A10 automatic rejection і A11 середовищні блокери не обходилися. A09 ліміт спроб не поновлювався: mandatory full повторив незмінний oracle, а не новий експеримент. Синтетичний процес не заміняє D01/людське приймання. Наступний доступний крок — D03.
