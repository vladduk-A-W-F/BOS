# A05 · збереження фінансової історії

11.09.2026 · версія 0.2.3-dev. Заморожений інвентар лишається 85 шляхів / 12 канонічних місць; A05 — погоджені 6–10 людино-днів, без повторного погодження.

## Виправлення

Salary/Transaction CRUD та ModelForm проходять спільні команди: поточний рядок читається після UPDATE-блокування, валідовані зміни й audit зберігаються одним atomic. Проведені суми, валюта, дата й джерело незмінні. paid без витрати не створюється через CRUD; справжня виплата лишається командою A02. Непроведені нарахування та ручні транзакції можна зберігати з валідацією.

Employee/Salary/Transaction DELETE, admin single/bulk і відповідні legacy команди архівують той самий PK. Нефільтрований manager зберігає джерела, унікальність періоду й суми звітів. Повтор не змінює timestamp/audit. Undo архіву відновлює той самий Employee, позначає журнал undone_at, не видаляє його. Звичайний save старої форми не переписує archived_at. Нове нарахування бере Employee lock до перевірки активності.

Захищено FK джерел зарплати та атрибуцію Transaction: контрагент, договір, філія не обнуляються при видаленні довідника. API повертає409, admin показує штатну причину PROTECT. Службове демонаповнення Branch відмовляється змінювати working або структуру з фінансовою історією. Схемні міграції не містять RunPython/переписування історичних значень.
