# C01 · уточнення чернеткового результату

12.09.2026. Root уточнив неоднозначне формулювання §3 C01_IMPLEMENTATION_CONTRACT_UA.md під час узгодження backend/UI. Це уточнення контракту, а не твердження, що попереднє однакове прочитання обома авторами було доведеним дефектом.

У незавершеному дорученні `result` може зберігати будь-який коректний буквальний текст до 2000 символів, зокрема «OK» або пробіли. `result_recorded` істинний тільки за змістовного тексту з trimmed length ≥3. Чернетковий текст не видається за завершений результат.

Новий перехід у done і виправлення результату вже завершеного доручення потребують явного FK відповідального та змістовного input result ≥3. `result=null` відхиляється. Старі NULL/історія не переписуються. Це не змінює 11 критеріїв приймання, дозволів, складських або грошових операцій.

Backend та UI мають однаково перевіряти це правило; actual red/green для короткої чернетки й відмови її використання як завершення додаються до C01 evidence. Саме уточнення ще не означає виконаного тесту або приймання.
