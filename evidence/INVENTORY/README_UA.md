## Команда незалежного повтору

Робочий каталог: `/workspace/scratch/c7b51e996a9f`.

```bash
demo-check-env/bin/python -B tmp/master_inventory_probe.py > tmp/master_inventory_root_verified.json 2> tmp/master_inventory_root_verified.stderr
```

Збережена точна копія скрипта: `probe.py`; первинний абсолютний шлях застосунку в ньому вказано явно. Для іншого checkout треба змінити тільки `ROOT` на його шлях, зберегти зміну як адаптацію середовища та виконати скрипт у Python-оточенні BoS. Скрипт створює нову синтетичну SQLite поруч із собою; наявні бази лише хешує. Не використовувати його як команду приймання.

Exit code: **0 — дефекти відтворено**. Stderr: **0 байтів**. Сценаріїв: **18**. Це результати стану «до виправлення». Результатів «після» немає: код не змінено за стоп-умовою 8.6.

Запити API та admin виконані через справжній Django Client із перевіркою CSRF. Для admin створено синтетичного адміністратора. Сценарій одночасної зарплатної виплати викликає справжній ORM і `mark_paid` у двох потоках із бар’єром після читання: жодних mocks або підмін бізнес-правил. Це не перевірка паралельних HTTP-запитів.

Повтор того самого `proposal_id` в окремому перевіреному сценарії `finish` повернув той самий результат без нових рядків. Це не доводить загальну ідемпотентність усіх дій.
