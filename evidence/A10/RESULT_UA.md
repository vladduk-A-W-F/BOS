# A10 · перевірена частина та відкриті умови

12.09.2026 · кандидат 0.2.10-dev · Linux / Python 3.12.14 / Django 6.0.5 / SQLite 3.53.1 / Waitress 3.0.2 / Caddy 2.11.1.

**Локальні backup, clean restore та операторський CLI перевірені. A10 загалом не прийнята: оновлення N → N+1 і rollback не реалізовані. Повний verify повернув 1.**

## Результат і межі

Керований сервер завершує прийняті запити й лише після цього дозволяє копіювання. Збережено точні SQLite-байти, 45 таблиць із ID/FK/сумами трьох валют, повний код, статику та всі приватні файли. Restore створює тільки нову установку; її нові UUID/секрет/cookie namespace відокремлюють запуск від оригіналу. Історичні записи користувачів, ролей, сесій і документів збережено. Перевірка HTTPS-входу та скачування оригіналу виконана на синтетичних даних.

Операторські `backup`, `serve`, `restore` мають виконуваний CLI. Після копіювання живий керований сервер очікує явного `resume`; `stop` завершує лише власні процеси. CLI restore прямо повідомляє, що його успіх стосується даних/коду; HTTP-перевірку окремо виконує наскрізна репетиція.

До виправлень відтворено: хибний успіх Waitress shutdown за активного writer; невірний ключ snapshot API; спробу валідації живого WAL замість sealed copy; публікацію готовності після пізньої помилки restore; аварійний SIGABRT через заблокований daemon stdin reader. Збережені фактичні журнали містять відмови до правок. Після мінімальних правок пройшли drain/control, 10/10 clean-restore сценаріїв та 8/8 CLI-сценаріїв. Окремі тести перевіряють відмови публікації COMPLETE через I/O.

## Що блокує завершення A10

Старий launcher, активне покоління та rollback потребують узгодженого контролю без втрати записів. Prototype ledger прийнятий тільки для current-owned та перевірки файлових ресурсів. Роботу агента над activation зупинила автоматична перевірка вмісту з повідомленням про можливий cybersecurity risk; її результат не є прийманням. Заблоковану дію не повторювали й не обходили. Ця частина лишається відкритою, робота над іншими задачами продовжується.

Немає приймання Windows, PostgreSQL, навантаження, відновлення після знеструмлення або всього MVP. Паспорт релізу не створюється.
